# JARVIS iOS MVP

## 개인용 USB 저장 공간

현재 Mac의 JARVIS 앱·코드·대화·DB·설정·빌드 자료는 USB의 APFS 저장 공간 `/Volumes/JARVISData`에서 관리합니다. USB 전용 앱은 실행 시 저장 공간 권한을 확인하고 연결 해제·저장 오류 시 작업을 중단하며 Mac 저장소로 대체하지 않습니다. USB 폴더의 실행·개발 연결과 로컬에 남기는 실행 자료, 분리 순서는 [USB 저장 공간 안내](Documentation/USBStorage.md)를 확인하세요. iPhone/iCloud 동기화와 로그인·안전 설정은 변경하지 않습니다.

## 대화형 코드 작업과 채팅 승인

Mac에서 App Server와 프로젝트 폴더를 연결한 뒤 기존 채팅창에 **“이 오류를 수정하고 테스트해줘”**처럼 요청합니다. Codex가 필요한 소스 범위, 변경안, 검증 명령을 차례로 제안하고 JARVIS가 검증·승인을 거쳐 실행합니다. helper build **2026.11.11.3**, codeVersion **3**이 필요하므로 최신 앱으로 빌드하고 보조 서비스를 재시작하세요.

- **소스 확인**에서 한 번만 허용, 이번 작업에서 허용, 허용 안 함을 선택합니다. 작업 허용은 표시된 파일·줄 범위의 반복 조회에만 적용되며 최대 8회 재사용합니다. 새 파일이나 더 넓은 범위는 다시 확인합니다.
- **파일 변경**은 변경 전후를 보고 파일별로 승인합니다. 백업·현재 원본 검사·쓰기 후 확인을 거친 뒤, 승인한 파일의 갱신 내용과 저장 결과를 다음 모델 요청에 반영합니다. 보호된 안전·인증·실행 코드는 기존 보호 규칙을 따릅니다.
- **검증 실행**은 한 번만 허용합니다. Swift build/test(선택적 test filter), Python unittest discovery, Xcode project/scheme build를 지원합니다. 검증은 소스 프로젝트를 읽기 전용으로 유지하고, 임시 빌드·테스트 경로에만 쓰기를 허용하며 네트워크를 차단합니다. 실행은 최대 60초입니다. 임의 셸 프로그램과 MCP 호출은 아래의 수동 도구 화면을 사용합니다.
- **진행 상황**은 채팅 안에 소스 요청·파일 저장·검증 실행·승인 대기·완료·중지로 표시합니다. 터미널 출력은 실행 중 실시간으로 표시합니다. 출력은 크기 제한 때문에 잘릴 수 있습니다.
- **결과 반영**은 출력을 검토·편집한 뒤 전송하고 이어갑니다. 출력의 민감정보를 제거하고 3,500바이트 이내로 줄일 수 있습니다. 실제 실행 성공·실패는 편집 내용과 별도로 전달합니다. 실패 후 자동 재시도하지 않습니다.

작업은 최대 12회 모델 요청·10분으로 제한하며 취소, 새 요청, 프로젝트·연결·모델 변경, 긴급 잠금 때 기존 승인과 대기 작업을 폐기합니다. 승인하지 않은 동작은 실행하지 않습니다. 인터넷 의존성 설치나 프로젝트 내부 쓰기가 필요한 테스트는 검증 샌드박스에서 실패할 수 있으며 실패 결과를 그대로 표시합니다.

SwiftPM 검증에는 중첩 샌드박스 충돌을 피하기 위한 `--disable-sandbox`를 고정 인자로 적용합니다. Codex의 외부 OS 샌드박스가 소스 읽기 전용·임시 경로 쓰기·네트워크 차단을 계속 적용합니다.

## Mac 프로젝트 도구 실행

App Server 연결과 프로젝트 폴더 연결을 완료한 뒤 채팅 입력창의 **+ → 셸·MCP·플러그인 도구 실행**을 엽니다. 실행할 프로그램·인자·프로젝트를 검토하고 **이번 실행 허용**을 누르면 한 번 실행합니다. 실행할 때마다 별도 승인이 필요하며, 중지와 긴급 잠금은 진행 중인 전용 프로세스를 종료합니다. helper build 2026.11.11.2 이상이 필요합니다.

- **셸·파일 명령**은 프로그램과 인자를 JSON 배열로 입력합니다. 예를 들어 `["/usr/bin/git", "status", "--short"]`입니다. Codex의 `command/exec` 샌드박스로 실행하며 프로젝트 쓰기, 최대 30초, 제한된 출력, 네트워크 차단을 적용합니다. 명령은 Mac의 다른 파일을 읽을 수 있으므로 인자를 검토해야 합니다. 종료 코드가 0인 경우만 실행 완료로 표시합니다. 파일 생성·수정·삭제 명령의 결과는 해당 명령의 동작에 따릅니다.
- **MCP**는 로컬 stdio 서버의 프로그램과 인자를 지정하고 도구 목록을 조회한 뒤 도구 이름과 JSON 인자를 입력해 호출합니다. 목록 조회도 프로그램을 실행하므로 승인해야 합니다. MCP 프로그램은 Mac 사용자 권한으로 실행되며 서버 구현에 따라 네트워크·파일에 접근할 수 있습니다. MCP 오류 응답은 실패로 표시합니다.
- **플러그인 MCP**는 사용자가 선택한 로컬 플러그인의 `.mcp.json`에서 `mcpServers`의 `command`, `args`를 불러와 같은 승인 경로로 실행합니다. 환경 변수·인증 설정을 포함한 구성, 원격 HTTP MCP, 플러그인 마켓 설치·OAuth·스킬·훅 실행은 아직 지원하지 않습니다.

이 화면은 사용자가 직접 검토한 도구를 실행합니다. 일반 채팅 모델이 자동으로 도구를 선택하는 기능은 아직 연결하지 않았습니다. 도구 출력은 이 화면에서 선택·복사할 수 있으며 대화 기록이나 모델 문맥에 자동 저장하지 않습니다. 실패·취소 후 부분적인 변경이 남을 수 있으므로 결과를 확인해야 합니다.

## Codex 작업 중 추가 메시지와 파일 목록

App Server 일반 채팅에서는 생성 중인 답변이 채팅에 실시간으로 나타납니다. 완료 응답을 검증한 뒤 대화 기록에 저장하며, 중지되거나 실패한 요청의 미완성 본문은 지웁니다. 코드 요청은 구조화된 변경안을 끝까지 받은 뒤 검증해 표시합니다. 실시간 응답을 사용하려면 내장 보조 서비스를 재시작해 helper build 2026.11.10.2 이상을 연결하세요.

응답을 생성하는 동안 채팅 아래에 **Codex 작업 중** 표시와 **중지** 버튼이 나타납니다. App Server의 대화나 코드 요청이 진행 중이면 추가 내용을 입력하고 **이 작업에 반영** 또는 Enter를 눌러 현재 작업에 전달할 수 있습니다. 한 요청에 최대 3회, 메시지당 1,800바이트입니다. 전달 실패 시 입력을 보존하고 자동 재전송하지 않습니다. 업데이트 후 내장 보조 서비스를 재시작하세요.

입력창의 **+ → 프로젝트 폴더 연결**로 폴더를 선택합니다. 연결된 폴더 이름이나 **+ → 프로젝트 파일 보기·첨부**를 누르면 파일을 검색하고 원하는 줄 범위를 첨부할 수 있습니다. 첨부한 범위는 입력창에 표시되며 전송 전에 제거할 수 있습니다. 다음 요청의 전송 버튼은 화면에 표시된 첨부 범위의 전송도 승인합니다. Codex가 추가 범위를 요청하면 채팅에서 따로 승인합니다. 목록은 전송 직전에 다시 읽습니다. 폴더 접근 거부나 연결 후 폴더가 교체된 경우는 목록이 실제로 비어 있는 경우와 구분합니다. 텍스트 소스와 일부 프로젝트 설정 파일을 지원합니다. 숨김 파일, 보호 경로, 링크, 바이너리와 지원하지 않는 형식은 콘텐츠 공유 대상에서 제외합니다.

App Server의 **+ → 이미지 첨부**에서 JPEG 또는 PNG 한 장을 선택하면 입력창에 미리보기가 나타납니다. 질문을 함께 입력하고 전송하면 축소한 JPEG를 Codex에 보냅니다. 입력 파일은 16MB, 전송 이미지는 긴 변 1,600픽셀과 1MiB로 제한합니다. 이미지 요청은 별도 임시 턴에서 처리하며 대화 기록에는 첨부 표시와 텍스트만 보관합니다. 코드 범위와 이미지는 별도 요청으로 보냅니다. 이미지 기능에는 helper build 2026.11.10.3 이상이 필요합니다.

## ChatGPT 대화 가져오기와 분기

사이드바의 **ChatGPT 대화 가져오기**에서 ChatGPT 데이터 내보내기 ZIP을 풀어 얻은 `conversations.json` 또는 분할 JSON 하나를 선택합니다. 파일은 최대 32MiB이며, 미리보기에서 가져올 대화를 고릅니다. 현재 분기의 사용자와 어시스턴트 텍스트를 별도 로컬 프로젝트에 복사하고, 이미 가져온 대화는 건너뜁니다. 가져온 메시지는 검색하고 읽을 수 있으며, 새 질문의 모델 문맥에 자동 포함하지 않습니다. 계정 설정, 도구 기록, 첨부 파일과 다른 분기는 가져오지 않습니다.

대화 본문에서 원하는 문장을 드래그하고 `⌘C`를 누르면 선택한 부분을 복사할 수 있습니다. 답변 헤더의 **여기서 새 대화로 분기** 버튼을 누르면 해당 답변까지 복사한 새 대화를 같은 프로젝트에서 엽니다. 분기에는 새로운 로컬 대화 ID가 부여됩니다.

## Mac Codex 작업 공간의 기능 범위

Mac의 Codex 작업 공간은 JARVIS의 일반 명령 처리와 분리되어 있으며, 전용 보조 프로세스가 Codex App Server를 호출합니다. 모델 선택 메뉴는 App Server가 반환한 모델과 추론 수준을 표시하고 모델을 새로 선택할 때 서버가 제시한 기본 추론 수준을 적용합니다. 최대 4페이지에서 최대 40개 모델을 읽습니다. CLI 연결과 서버 목록을 아직 받지 못한 상태에서는 추천 및 최근 모델을 표시합니다.

| 기능 | JARVIS에서의 동작 |
| --- | --- |
| 로그인, 계정 플랜, 모델과 추론 수준, 계정 한도 | 전용 App Server 연결에서 조회 |
| 프로젝트와 대화 | Mac에서 관리하고 제목 및 메시지 본문으로 검색 |
| 소스 읽기, 변경안, 적용과 복구 | 프로젝트 폴더 연결 후 범위별 전송 및 파일별 적용 승인 |
| 실시간 응답 | App Server 일반 채팅에서 사용 가능 |
| 이미지 첨부 | App Server 채팅의 + 메뉴에서 JPEG 또는 PNG 한 장 |
| 공식 앱 대화 가져오기 | ChatGPT 내보내기 JSON의 텍스트 대화를 선택해 Mac으로 복사 |
| 답변 시점에서 대화 분기 | 답변 헤더의 분기 버튼으로 같은 프로젝트에 새 대화로 복사 |
| 셸·파일 명령 | + 메뉴에서 실행별 승인 후 Codex 샌드박스 실행 |
| MCP·플러그인 MCP | + 메뉴에서 로컬 stdio 서버와 도구를 선택해 승인 실행 |
| 대화형 개발 작업 | 모델의 소스·변경·검증 제안을 채팅에서 승인하고 실행 결과로 후속 처리 |
| 임의 프로그램·MCP 자동 호출, 웹 검색, 컴퓨터 제어, 하위 에이전트 | 전용 모델 대화에서는 실행 제한 |

App Server 연결 설정의 **계정 상태 새로 고침**은 로그인과 ChatGPT 플랜을 확인한 뒤 모델 목록과 사용량을 갱신합니다. 로그인 완료 후에도 같은 확인을 실행합니다. 플랜과 확인 시각만 화면에 유지하며 이메일과 인증 정보는 반환하지 않습니다. 이 기능에는 helper build 2026.11.11.1 이상이 필요합니다. JARVIS는 전용 App Server 환경과 로컬 대화 저장소를 사용합니다. 공식 앱의 대화는 위의 내보내기 파일로 가져올 수 있으며, 양방향 대화 및 설정 동기화는 지원되지 않습니다.

## Codex 입력창의 AI 선택·잔여 사용량

프로젝트 이름 오른쪽의 **폴더 설정 아이콘** 또는 프로젝트 우클릭 메뉴의 **접근 폴더 선택…**에서 해당 프로젝트의 접근 폴더를 선택할 수 있습니다. 빈 프로젝트에서도 그 프로젝트 안에 대화를 준비하며, 폴더 연결 전 대상 프로젝트와 실제 경로를 확인합니다. 프로젝트를 바꾸면 이전 폴더 접근을 해제하므로 다시 선택해야 합니다. 폴더 권한은 다른 프로젝트로 자동 이전하지 않습니다.

대화 목록에 마우스를 올리면 오른쪽에 **휴지통**이 나타납니다. 누른 뒤 **삭제하시겠습니까? → 삭제**를 선택하면 해당 대화의 로컬 기록을 삭제합니다. 연결한 실제 폴더·소스 파일과 OpenAI 서버 기록은 이 동작으로 삭제되지 않습니다. 우클릭 메뉴의 삭제도 같은 확인 절차를 사용합니다.

입력창의 모델 선택 옆에 AI 선택 버튼을 표시합니다. 현재 연결 대상은 Codex이며 Claude는 **연결 준비 중**으로 비활성 표시합니다. Claude 실행·로그인·인증 정보 접근은 연결하지 않습니다. 승인 범위와 기존 파일 변경 확인 절차는 유지합니다.

App Server 연결에서는 공식 `account/rateLimits/read`가 제공하는 계정 한도의 잔여 비율을 표시합니다. 사용량을 누르면 집계 구간·갱신 시각·마지막 확인 시각을 보고 새로 고침할 수 있습니다. 연결 확인 및 응답 수신 후에도 갱신합니다. CLI 연결·서버 미제공·조회 실패 시 **확인 불가**로 표시하며 잔여 토큰 수나 금액을 추정하지 않습니다. 이 조회는 모델 질문을 생성하지 않습니다. 내장 보조 서비스를 다시 시작해 helper build 2026.11.04.6을 사용하세요.

## Mac Codex에서 JARVIS 소스 수정

소스 확인 요청에서 여러 파일 중 하나가 실패해도 나머지 정상 파일의 미리보기·승인은 유지합니다. 긴 범위는 파일당 32KiB·전체 96KiB 안에서 완전한 줄 단위로 줄이고 실제 준비된 범위를 표시합니다. 제외된 파일·줄 범위 오류·비밀 키 감지 이유를 구분하며, 키가 감지된 파일은 전송하지 않습니다. 이 변경은 보조 서비스 재시작 후 사용하세요(helper build 2026.11.04.5).

멀티 에이전트의 기본 Codex 채팅에서 JARVIS 코드를 수정할 수 있습니다. 연결 설정의 **App Server**와 로그인 상태를 먼저 확인하세요. 별도 코드 수정 화면으로 이동하지 않습니다.

1. 채팅 입력창 위 **프로젝트 폴더 연결** → 폴더 선택·접근 승인.
2. 기본 입력창에서 수정 요청 전송. 요청·상대 파일 목록·최근 최대 3회의 코드 대화 문맥을 제공하고, Codex가 필요한 파일 범위를 요청합니다.
3. 대화 안의 **코드 읽기·OpenAI 전송 허가 요청**에서 경로·줄 범위를 확인하고 허용하거나 거절합니다. 허용한 범위만 전송합니다.
4. 같은 대화에서 파일별 변경 전후 검토 → **한 번만 허용 · 적용 후 계속**. 원본을 재확인하고 백업 후 저장합니다.
5. 대화의 **변경 기록·복구**에서 전후 내용을 확인해 복구를 승인할 수 있습니다. 이후 다른 작업으로 수정된 파일은 덮어쓰지 않습니다.

한 작업은 최대 12회 모델 요청·10분입니다. 소스 전송은 검토한 범위를 승인하며 이번 작업 허용의 범위를 넘으면 다시 확인합니다. 새 입력·거절·중지·대화/모델/연결 변경·긴급 잠금은 보류 요청을 취소합니다. 프로젝트를 바꾸거나 화면을 떠나면 폴더 접근을 해제합니다. 자연어 대화 기록을 Mac에 보관하며 새 작업에서 이전 소스 첨부와 변경안을 자동 재전송하지 않습니다. 소스에 포함된 개인정보는 직접 확인해야 하며, 알려진 키 형식이 감지되면 전송을 차단합니다. 모든 개인정보를 자동 탐지한다는 보장은 없습니다.

새 소스 파일은 기존 폴더 안에 생성할 수 있습니다. 한 요청은 최대 8개 파일·96KiB 코드 범위이며 파일당 600줄·32KiB, 로컬 원본은 1MiB까지입니다. 큰 파일은 필요한 줄 범위를 선택합니다. 안전 정책·인증·실행기·Codex 연결·AGENTS·빌드 설정 코드는 보호합니다. 일반 대화의 파일·셸 권한을 일괄 허용하지 않으며 MCP·자동 셸 실행은 포함하지 않습니다. 저장한 변경을 실행 중인 앱에 반영하려면 별도로 빌드·실행해야 합니다. 변경안 수신과 파일 저장을 빌드·테스트 성공으로 표시하지 않습니다.

구조·검증·제한: [Codex 코드 수정](Documentation/CodexCodeEditing-2026-11-04.md).

## 호출 음성·비동기 재생 안정화 (2026-10-24)

- “네.” 호출 응답을 포함한 TTS는 요청 시 선택한 음성을 한 번 결정하고 시작 재시도에도
  같은 음성을 사용합니다. 재시도 때 저장된 설정을 무시하던 경로를 제거했습니다.
- 저장한 음성이 잠시 목록에 없어도 설정을 자동 삭제하지 않습니다. 설정에 사용 불가로
  표시하고 다음 요청에서 다시 확인합니다. 실제 사용이 불가능하면 대체 음성을 사용하며
  **음성 안정성 진단 → 저장한 음성 사용 불가**에 횟수만 집계합니다.
- 미리 듣기는 본 응답과 같은 TTS 구현을 사용합니다. 음성 변경·미리 듣기는 진행 중인
  대화/대기 실행을 중지하며, 설정 화면 이탈·비활성화·새 명령에서 미리 듣기도 취소합니다.
- 이미 시작된 문장이 취소되면 처음부터 다시 읽지 않습니다. 시작 실패만 최대 한 번
  같은 음성으로 재시도하며, 오래된 재생 콜백과 중복 완료 콜백은 새 대화를 건드리지 않습니다.
- 비활성 상태에서는 단축어 대기 플래그를 소비하지 않습니다. 명령과 호출 플래그가 함께
  있으면 명령 하나를 처리하고 오래된 호출 플래그를 지워 뒤늦은 “네.” 응답을 방지합니다.
- 노래 찾기 단축어는 음성 안내/대기 이후에도 취소·안전 잠금을 재검사합니다.
- 이미 예약된 TTS 알림은 미리 생성한 파일을 사용하므로 음성 설정 변경만으로 다시
  만들지 않습니다. Siri 자체 응답은 JARVIS의 TTS 설정과 별개입니다. 실제 iPhone의
  잠금·Bluetooth·Siri 인계 음질/출력은 실기기 확인이 필요합니다.

점검 범위와 재현 절차: [안정성 점검 기록](Documentation/StabilityReview-2026-10-24.md).

## 알람·캘린더 수동 동기화 (A 묶음)

개발 공간에 들어가면 **iCloud 공유 프로젝트**, **멀티 에이전트** 두 개의 입장 버튼이 표시됩니다.
기존 공유 폴더·파일 관리·DB 기능은 iCloud 공유 프로젝트 안에 그대로 유지합니다.

연결 설정에서 **CLI / App Server**를 명시적으로 선택합니다. 기존 CLI는 유지하고 App Server는 전용 비공개 설정·로그인 저장소와 stdio 프로세스를 사용합니다. 전환하면 로그인·준비 상태를 다시 확인하며 실패한 요청을 다른 방식으로 자동 재전송하지 않습니다. 이번 App Server 단계는 텍스트 대화만 지원하고 파일·명령 도구는 계속 차단합니다.
Mac 앱의 **보조 서비스 시작·자동 연결**로 연결할 수 있습니다. 기존 수동 실행·연결 파일 선택도 유지합니다.
Codex 형태의 사이드바에서 프로젝트·대화를 생성·이름 변경·삭제하고, 오른쪽 대화창에서
선택한 모델과 텍스트 대화를 이어갑니다. 프로젝트 없이 첫 메시지를 전송하면 `일반 대화` 프로젝트와 대화방을 만들고, 상단 `새 대화`도 일반 대화 안에 생성합니다. 프로젝트 안의 새 대화 버튼은 해당 프로젝트를 사용합니다.

모델 버튼은 연결 전에도 추천 모델 8개를 이름·선택 체크 표시가 있는 팝업으로 보여줍니다. 캐시가 비어 있거나 연결이 해제돼도 선택 목록은 유지하며, 연결 후 받은 모델 정보와 지원 추론 수준을 병합합니다. 추천 목록이 계정 사용 권한을 보장하지는 않습니다. 입력창 안내 문구와 커서는 같은 네이티브 텍스트 컨테이너에서 그려지며 Enter 전송·Shift+Enter 줄바꿈을 지원합니다. 한글 조합 중 Enter는 글자 확정만 하고, 키를 누르고 있어도 반복 전송하지 않습니다.
로그인 확인은 보조 프로그램 프로토콜도 검사합니다. CLI는 버전 2·3, App Server는 버전 3을 요구하며 응답의 연결 방식도 검증합니다. 구버전이 실행 중이면 로그인돼 있어도 대화 준비 완료로 표시하지 않고, 터미널 프로그램 재시작과 연결 파일 재선택 방법을 안내합니다. 로컬 HTTP 400/401/403/404/405 거절과 연결 불가를 실제 모델 응답 대기 후 결과 불명 상태와 구분하며 자동 재전송하지 않습니다.
모델은 최근 CLI 모델 목록 또는 직접 입력한 ID를
사용합니다. 목록은 현재 사용 권한을 보장하지 않습니다. 입력창에서 사용자가 누른 Enter 또는 전송 버튼을 현재 메시지·모델·대화의 전송 확정으로 처리하고, 반복 토큰 알림·전송 확인 팝업은 표시하지 않습니다. 이 동작은 매번 안전 정책과 연결·중복 검사를 거치며 모델·자동화의 전송 승인이 되지 않습니다. 계정 사용 한도는 계속 적용됩니다. 프로젝트는 대화 정리 공간이며 파일 폴더에 연결되지 않습니다.

입장만으로 API를 호출하거나 파일 권한을 부여하지 않습니다. Mac 앱 샌드박스는 유지합니다.
2026-11-03 실제 테스트에서 고정 질문의 Codex 답변 수신을 확인했습니다. 비활성 코드 실행 호스트의 정확한 경고 문구만 구분하며, 실제 오류·도구 실행·빈 답변은 계속 실패 처리합니다. 보조 프로그램 수정 후에는 터미널에서 재시작하고 연결 파일을 다시 선택해야 합니다.

OpenAI 연결·학습 결과·명령 연습·정정 검토·기억 관리도 같은 방식입니다.
문항 상세·기억 편집·일정 일간/검색 등 실제 하위 화면은 부모–자식 이동을 유지합니다.

“안녕이라고 적혀있는 메모를 만들어줘”, “안녕이라는 문구가 적혀있는 txt 파일을 만들어줘”도
이제 파일 명령 초안으로 처리합니다. 먼저 개발 공간에서 공유 폴더를 연결해야 합니다.
파일 위치를 물으면 `메모/인사.txt`처럼 공유 폴더 기준의 경로를 답하고, 이어 표시된 경로·내용을
승인해야 저장합니다. 상위 폴더를 임의 생성하거나 파일명을 추측하지 않으며 기존 파일을 덮어쓰지
않습니다. 취소·새 명령·만료·폴더 연결 변경 시 초안을 버립니다. Apple 메모 앱 생성 기능은 아닙니다.

- 기기별 비공유 SQLite DB에 항목·변경 이력·전송 대상·삭제표식·충돌·수집 기준을 하나의
  트랜잭션으로 저장합니다. DB 자체를 iCloud에 올리지 않습니다. 기존 iPhone 알람·일정 JSON
  저장소는 보존하며 명시적 수집 때만 이 별도 동기화 DB에 연결합니다. 아직 기존 운영 저장소를
  SQLite로 대체하거나 자동 추적하지 않습니다.
- 공유 폴더에는 저장소 식별자와 체크섬 이름의 불변 변경 묶음을 기록합니다. 항목/수신확인/
  삭제표식/충돌/복구 폴더는 구조를 준비하지만 A의 실제 교환은 변경기록을 사용합니다.
  삭제표식·충돌은 변경기록과 로컬 DB에 보존하며 충돌 해결 UI는 B 단계입니다.
- 내보내기는 새 기록만 최대 1,000변경·4 MiB씩 나누며 전체 16 MiB·2,000파일·32기기
  한도를 쓰기 전에 확인합니다. 한도 초과 시 기존 파일을 삭제하거나 덮어쓰지 않습니다.
  날짜·시각은 항목에 기록된 시간대로 표시하며, 로컬 DB·백업의 공유 폴더 내부 배치를 차단합니다.
- 가져오기 결과는 **동기화 DB 병합·예약 반영 대기**입니다. 기존 iPhone 목록이나 실제 OS
  예약을 수정하지 않으며 Mac의 월간 캘린더·알람 편집 및 iPhone 예약 연결은 B/C 단계입니다.
- 검토·승인은 폴더·DB 버전·자료 해시·2분 유효기간에 묶이며 한 번만 적용됩니다. 변경된 자료,
  손상/미지원 형식·링크·부족한 기준 이력은 보류합니다. 원격 수신을 재수정으로 내보내지 않습니다.
- `알람`, `캘린더`, `시스템`은 초기화 전부터 일반 파일 도구의 생성·저장·이동·삭제를 차단합니다.
  이 이름을 포함한 상위 폴더의 일괄 이동·삭제도 거절합니다. `메모` 문서는 기존 기능을 유지합니다.
- 각 DB 변경 전 로컬 `Application Support/JARVIS/SharedSync/백업`에 이전 DB 상태를 남깁니다.
  iPhone 수집 원본(기기별 예약 식별자 포함)은 그 기기 내부에만 백업합니다. 백업의 자동 삭제·복구
  화면은 아직 없으며 필요 시 보존된 자료를 통한 별도 복구 작업이 필요합니다.
- API 키 전용 필드·안전 잠금·승인·OS 예약 ID는 공유하지 않습니다. 제목·장소·메모 등 실제 내용은
  선택한 폴더 접근자에게 전달될 수 있습니다. 비밀정보 자동 완전 탐지는 하지 않습니다.
- 자동 동기화·상대 기기 수신 확인·백그라운드 예약 반영은 아직 없습니다. 실제 iCloud 전송은
  두 기기로 확인해야 하며, 파일 기록 성공을 원격 반영 완료로 안내하지 않습니다.

형식·한도·실기기 검증 절차: [수동 데이터 동기화 안내](Documentation/SharedDataSync.md).

## iCloud 공유 프로젝트 · Mac 앱

메인 왼쪽 위 **개발 공간(망치 아이콘) → iCloud 공유 프로젝트**에서 시스템 폴더 선택창으로 iCloud Drive의
프로젝트 폴더 한 곳을 선택합니다. Mac에서는 별도 프로젝트
`JarvisMac/JarvisMac.xcodeproj`의 **JarvisMac** 스킴을 실행하고 같은 폴더를 선택합니다.
Mac에 표시되는 앱 이름과 앱 파일명은 **JARVIS**(`JARVIS.app`)입니다.
Mac 앱 아이콘은 사용자가 제공한 하늘색 J·궤도 로고이며 macOS 크기별 이미지로 포함합니다.
이전 IP·인증서 방식은 계속 비활성화 상태이며 새 기능은 서버를 열지 않습니다.

- 양쪽에서 폴더 탐색, UTF-8 코드·텍스트 열기, 직접 편집, 변경 전후 확인 후 저장,
  빈 코드 파일 생성이 가능합니다. 저장은 파일별 승인을 요구하며 새 파일은 덮어쓰지 않습니다.
- **공유 폴더 명령**으로 폴더/TXT 메모 생성·메모 수정·이동/이름 변경·복구함 삭제를 지원합니다.
  iPhone 음성·채팅과 양쪽 개발 공간의 명령 입력에서 사용할 수 있습니다. Mac 앱은 현재
  자체 음성 대화가 없으므로 개발 공간의 명령 입력을 사용합니다. 버튼으로도 새 폴더·메모를
  만들고 각 항목의 **관리**에서 이동/이름 변경/삭제할 수 있습니다.
  모든 명령 경로는 허용 폴더 기준이며 화면의 현재 하위 폴더나 오래된 대상을 추측하지 않습니다.
  상위 폴더가 없으면 실패하고, 모호한 지시/절대 경로/상위 탈출/와일드카드는 실행하지 않습니다.
  생성/수정도 확인을 받으며 이동·삭제는 높은 위험으로 분류해 원본·대상 경로를 재확인합니다.
  삭제는 프로젝트 안의 **JARVIS 복구함**으로 이동하며 영구 삭제 API는 없습니다.
  이번 연결의 복구 버튼 또는 재실행 후 항목 관리의 명시적 이동으로 복구할 수 있습니다.
  폴더 작업은 최대 500항목·깊이 12·총 8 MiB의 지원 텍스트 트리만 다루며 숨김·링크·미지원
  파일이 섞여 있으면 통째 작업을 차단합니다. 승인 중 하위 내용이 바뀌면 기존 승인을 거절합니다.
- 폴더 권한은 현재 실행 동안만 유지합니다. 재실행하면 다시 선택하며, 폴더를
  선택하는 것만으로 외부 AI 전송·코드 실행·빌드 권한이 생기지 않습니다.
- 선택 폴더 접근과 저장은 `AssistantIntent.sharedProject`와 `SafetyPolicyEngine`을 통과합니다.
  안전 잠금 시 조회·저장은 차단하고 중지·접근 해제는 유지합니다. 잠금은 기기별입니다.
- 파일은 `NSFileCoordinator`로 조정하고 저장 전 원본 해시와 제공자의 충돌 버전을
  확인합니다. 변경된 원본은 덮어쓰지 않으며 초안을 복사한 뒤 다시 열어 비교합니다.
  오프라인 동시 편집의 전역 잠금·자동 병합·버전 복구는 아직 제공하지 않으므로 Git 백업을 유지하세요.
- 기기 내 저장을 확인해도 다른 기기 동기화 완료로 표시하지 않습니다. 네트워크,
  iCloud 저장 공간·다운로드·파일 제공자 상태에 따라 지연/실패할 수 있습니다.
- 최대 256 KiB의 UTF-8 파일과 폴더당 500개 항목을 지원합니다. 숨김·심볼릭 링크·
  하드 링크·일부 민감 이름 파일 및 빌드 폴더는 제외합니다. 완전한 비밀정보 탐지나
  적대적 로컬 프로세스에 대한 파일 시스템 샌드박스 대체는 아닙니다.
- 코드·경로를 모델, 채팅, 기억, 학습 데이터로 자동 전송하지 않습니다. 파일 내용도
  명령이 아닌 데이터입니다. 임의 터미널 실행, 영구 삭제, REA, AI 코드 생성은 포함하지 않습니다.
- Mac 앱은 개발 공간 전용 첫 버전이며 iPhone의 음성·알람·캘린더·대화 전체를 이식한
  앱이나 하나의 공용 추론 서버가 아닙니다. 로컬 폴더를 선택하면 iCloud 동기화되지 않습니다.

설치·기기 간 확인 절차는 [공유 프로젝트 사용 안내](Documentation/SharedProject.md)를 참고하세요.

## 개발 공간 · Mac 프로젝트 읽기 (보류)

현재 Mac 연결 화면·저장소 구현과 진입 버튼은 `#if false`로 컴파일에서 제외했습니다.
로컬 네트워크 권한 설명과 Mac 서비스의 CLI 실행도 주석 처리하여 기존 JARVIS 화면만 사용합니다.
연결 정보·인증서 파일은 삭제하지 않았으며, 아래 내용은 재활성화를 위한 보관 문서입니다.
이미 터미널에서 서비스를 실행했다면 해당 터미널에서 Control-C로 종료해야 합니다.

재활성화 후에는 메인 왼쪽 위 **개발 공간**에서 Mac이 허용한 프로젝트 한 폴더를 탐색·읽기·검색합니다.
사용자가 Mac의 HTTPS 서비스를 직접 시작하고 주소·인증서 지문·프로젝트를 확인해 연결합니다.
연결 정보는 아이폰 Keychain에 보관하고 파일은 AI·채팅·장기 기억으로 자동 전송하지 않습니다.
안전 잠금은 조회도 차단하며 화면 이탈·취소·연결 해제 뒤 늦은 결과는 폐기합니다.
REA 없이 동작하며 파일 수정·명령 실행·자동 코드 설명은 아직 지원하지 않습니다.
같은 로컬 네트워크와 실행 중인 Mac이 필요합니다. 연결·중지 절차와 파일 제한은
[Mac 읽기 서비스 안내](Tools/MacBridge/README.md)를 확인하세요.

## A 묶음 안정화: 알람·캘린더 실행 / 저장 / 예약

- 화면·음성의 알람 변경, 캘린더 저장·삭제·전체 삭제, 유지보수는 `LocalDataExecution`의 안전 판단과 단일 쓰기 경계를 사용합니다. 모델용 기능에는 유지보수를 등록하지 않습니다. 전체 삭제·백업 복구는 별도 확인이 필요하고 안전 잠금 중에는 차단합니다. 알람 종료의 기존 안전 예외는 유지합니다.
- 편집 화면의 취소·닫힘·백그라운드 전환은 진행 중 저장 작업의 취소를 요청합니다. 이미 전달된 시스템 작업은 복구 또는 확인 필요 상태로 처리하며, 취소가 곧 미실행을 뜻하지는 않습니다. 저장 중 중복 저장과 스와이프 닫기를 막습니다.
- 알람 변경 전 원래/변경 후 레코드를 로컬 저널에 기록하고, 실제 시스템 예약 확인 뒤 목록을 저장합니다. 실패·취소 시 정확히 이전 예약으로 복구를 시도하며, 복구를 확인하지 못하면 저널과 경고를 남기고 추가 변경을 막습니다. 알람 화면의 **중단된 변경 확인·복구**에서 개별 확인 후 복구합니다. 이미 울린 알람이나 이미 시스템에 전달된 효과를 무조건 되돌린다는 보장은 아닙니다. 전체 삭제가 중간 실패하면 앞서 삭제한 항목은 삭제된 상태일 수 있으므로 목록과 경고를 확인해야 합니다.
- 알람·일정 목록은 앱 Application Support의 보호된 원자적 JSON 파일에 저장하며 이전 UserDefaults 배열은 첫 정상 쓰기 시 검증 후 이전합니다. 최근 정상 데이터 백업을 유지합니다. 읽기 실패를 정상 빈 목록으로 간주하지 않고, 백업이 있으면 읽기 전용 목록과 복구 버튼을 표시합니다. 복구에는 별도 확인이 필요하며 손상 원본을 보존합니다. 백업은 최신 변경을 포함하지 않을 수 있고 완전한 재해 복구나 기기 간 동기화를 제공하지 않습니다. 로컬 백업·손상 원본에는 이전 알람/일정 내용이 남을 수 있습니다.
- 캘린더 화면과 음성은 같은 저장·삭제 경로를 사용하고 오래된 수정 대상을 거절합니다. 수정 실패 시 이전 일정 목록을 복구하고 예약 확인 필요를 남깁니다. 새 일정만 저장되고 알림이 실패하면 부분 완료로 안내합니다. 미완료 상태는 앱 재시작 후에도 표시하며 **알림 재예약·상태 확인**에서 확인 후 재예약합니다. 저장·시스템 예약은 서로 다른 저장소라 원자적 동시 커밋을 보장하지 않습니다.
- 일정 알림은 지난 일정 40개가 아니라 전체 일정의 실제 알림 시각이 빠른 순서로 예약합니다. 반복 일정은 370일 범위·일정당 최대 64회 후보로 계산하며, 앱 전체 예약 공간에서 다른 알람을 제외하고 최대 48개/여유 8칸을 남기는 이동 범위를 사용합니다. 예약 범위와 제한을 캘린더에 표시합니다. 장기간 앱을 열지 않으면 반복 알림이 소진될 수 있으며 무기한 백그라운드 갱신을 보장하지 않습니다.
- 예약 교체는 기존 요청을 보관하고 실패 시 복구를 시도하며, 실패한 갱신을 성공한 갱신 시각으로 기록하지 않습니다. 음성 파일 생성에는 취소·시간 제한을 적용하고, 알람 TTS 생성 실패를 묵음 성공으로 처리하지 않습니다. 일정 음성 생성 실패의 기본 알림음 대체는 기존 동작입니다. 실제 소리가 들리는지는 iPhone의 잠금·집중·무음·오디오 경로 환경에서 별도 검증해야 합니다.

개인 iPhone과 Apple Watch에서 사용하는 음성 비서입니다. 카카오톡 연동은 제외하며 날씨 수치에 기반한 우산·복장 조언은 지원합니다.

## 검증된 개선 운영 · 개인용 명령 분류 검토

10문항 결과 목록과 문항 상세에 ‘자비스가 사용자에게 하는 응답’을 표시합니다. 실제 학생의 판단을 기준으로 하며 교사의 정답으로 바꾸어 표시하지 않습니다. 일반 대화는 기기 내 대화 모델의 답변을 프로필·기억·이전 대화 없이 생성해 저장하고, 재질문은 실제 반환한 문장을 보관합니다.

지원 명령의 후속 출력은 **가상 상황 전체 응답**으로 첫 안내·결과 본문·추가 제안·재질문을 순서대로 저장하고 문항 상세에서 전부 펼쳐 보여줍니다. 종합 브리핑·일정·날씨·시각은 실제 앱의 `BriefingService` 출력 포맷터에 가상 입력을 넣습니다. 예: 오후 2시 프로젝트 회의와 오후 5시 공원 산책, 기온 8도와 강수 확률 80%를 사용한 전체 브리핑. 문항 번호에 따라 일정 없는 맑은 날·날씨 통신 실패 상황도 확인합니다. 날씨 제안은 기존 `WeatherAdviceEngine`으로 계산합니다. 음악 식별·음량·재생 중지·YouTube·주변 장소·길 안내에는 명시적인 모의 결과를 사용하고, 미연결 기능은 모의 실행 미지원이라고 표시합니다. 승인이 필요한 경우 임의로 승인하지 않고 재질문에서 멈춥니다.

가상 일정·날씨·식별곡·장소·외부 전달 결과는 실제 사용자 데이터나 실제 실행 성공이 아닙니다. `AssistantViewModel`과 모든 실제 도구를 끝까지 통과한 E2E 기록이라고 주장하지 않습니다. 실제 날씨·개인 일정·위치·연락처 조회, 앱 전환, 알람 변경, TTS 재생, 추가 OpenAI 요청은 수행하지 않습니다. 가상 날씨 실패는 실제 네트워크로 재시도하지 않습니다. 이전 기록의 누락된 문장은 사후에 생성하지 않으며 새 연습부터 전체 응답을 저장합니다. 의도 정확도와 별도로 출력 확인용이며 전체 응답을 모델 가중치 학습이나 개선 성공으로 집계하지 않습니다.

설정 → OpenAI → 학습 결과 → 명령 자동 학습 연습에서 기존 10문항 생성·개별 적용·폐기·실패 검토를 사용합니다. 사용자 정정 후보는 같은 화면의 ‘사용자 정정·실패 후보 검토’에서 기존 수집 동의를 거쳐 검토합니다. 실제 대화를 자동 연습의 생성 프롬프트로 보내지 않고, 기능별 횟수와 고정 가상 예제를 사용합니다. 문항 번호별로 구어체·어순·정중한 질문·군더더기·짧은 표현·띄어쓰기·가벼운 음성인식 오류·간접 요청·동의어·복합 표현을 요청합니다. 생성이나 교사의 자체 확신을 정답 보증으로 간주하지 않습니다.

적용·복구 시 예제를 아직 배포하지 않은 채 다음을 검사합니다.

- 기존 `CommandEvaluationCorpus.standard` 전체의 라우터·예제 조회 변경 전후 비교: 정확도 95% 이상이며 새 실패가 없어야 합니다.
- 별도 보관한 12개 명령: 실제 사용 가능한 로컬 라우터·의미 모델을 변경 전후 호출합니다. 지원 기기가 아니면 로컬 기본 분류 결과이며 OpenAI를 학생으로 사용하지 않습니다. 별도 문장은 생성·교사 프롬프트에 보내지 않고 정확히 같은 정규화 문장을 연습·승인 자료로 적용하지 못하게 막습니다.
- 의미 추론 우회 방지 사례와 확인·긴급 잠금·고위험 제안 차단 정책을 검사합니다. 새 실패나 안전 실패가 생기면 사용자 승인 여부와 무관하게 대기 상태로 보류합니다. 검증 중 취소·잠금·설정 변경·만료 시 늦은 결과로 적용하지 않습니다.

결과에는 기존 점수·별도 문장 점수·새 실패·문장별 전후 판단을 최근 50회까지 기록합니다. 이 고정 세트는 반복 사용하는 제한된 평가이며, 같은 문장을 다시 맞히거나 별도 점수가 높아졌다고 범용 일반화·가중치 학습 성공으로 표시하지 않습니다. 실제 기기 실행 성공률이나 모든 대화 능력에 관한 인증도 아닙니다. 실기기 로컬 모델 결과는 기기·모델의 비결정성에 따라 달라질 수 있어 보수적으로 보류할 수 있습니다.

명령 예제 변경 직전 버전을 최근 20개까지 보관합니다. 사용자가 선택한 버전도 현재 규칙과 같은 평가를 다시 통과해야 복구합니다. 이후 철회·폐기한 예제가 해당 버전에 포함될 수 있음을 확인하고 승인해야 합니다. 권한·안전 정책·자격 증명·모델 가중치는 복구하지 않습니다. 전체 삭제는 복구본과 평가 기록까지 삭제하므로 복구로 삭제 자료를 되살리지 않습니다.

각 연습 묶음에 요청 시도 수와 응답에서 확인한 입력·출력 토큰을 기록합니다. 계정의 현재 모델 단가(100만 토큰당 USD)를 직접 입력하면 **다음 연습부터** 해당 단가를 저장해 확인된 토큰의 예상 비용을 표시합니다. 미입력·유효하지 않은 단가는 ‘금액 미산정’입니다. 실패·취소 요청의 청구 토큰과 다른 API 사용은 이 추정에 포함되지 않으며 공식 청구 내역이 최종 기준입니다. 금액은 지출 상한이 아니며 기존 일일 요청 한도·1회 최대 20요청·취소·자동 재시도 금지를 유지합니다.

### API·저작권·개인정보 범위

2026-10-16 확인한 [OpenAI Services Agreement](https://openai.com/policies/services-agreement/) §3.3, §4 및 Permitted Exception에는 경쟁 모델 개발 제한, 비배포 분류 모델 등에 대한 예외, 입력 권리와 출력 검토에 관한 조건이 있습니다. 이번 기능은 보수적으로 **개인용 앱의 짧은 명령 분류 검토·평가·승인 예제 보완**으로 제한합니다. 모델 가중치 학습·미세조정·증류·범용 경쟁 모델 개발·자료 내보내기·재배포는 구현하지 않습니다. 배포·상업화·사용 목적 변경 전 적용 계약·최신 약관·제3자 권리를 다시 검토해야 합니다. 이는 법률 자문이나 법적 무위험 보장이 아닙니다.

기존 사용자도 검토 범위를 읽고 ‘설정 확인 후 적용’을 승인해야 연습·예제 사용이 활성화됩니다. 가상 명령의 독창적인 변형만 요청하며 타인의 대화·기사·가사·개인정보를 자동 입력하지 않습니다. 출력의 유사성이나 권리 문제를 완벽하게 판별할 수 없으므로 사용자가 문항별로 검토하고 의심스러운 결과는 폐기해야 합니다. API는 `store: false`를 유지하지만 이것이 모든 서버 보관을 없앤다는 뜻은 아닙니다. [공식 데이터 보관 안내](https://developers.openai.com/api/docs/guides/your-data)를 따릅니다. 검증 테스트에서는 가짜 교사·학생만 사용하며 실제 유료 API나 기기 도구를 실행하지 않습니다.

## 실행 준비

1. Mac App Store에서 최신 안정 버전 Xcode를 설치합니다.
2. `Jarvis.xcodeproj`를 Xcode로 엽니다.
3. 프로젝트 탐색기에서 `Jarvis` 타깃을 선택합니다.
4. **Signing & Capabilities**에서 본인의 Apple 계정 Team을 선택합니다.
5. Bundle Identifier `com.minhyuc.jarvis`가 충돌하면 고유한 값으로 변경합니다.
6. 실제 iPhone을 Mac에 연결하고, iPhone에서 개발자 모드를 활성화합니다.
7. 실행 대상을 연결된 iPhone으로 선택한 뒤 Run을 누릅니다.

시뮬레이터보다 실제 iPhone 테스트를 권장합니다. 마이크, 화면 잠금, Siri·음성 단축어, App Shortcut은 실제 기기에서 확인해야 합니다.

Apple Watch까지 설치하려면 Xcode의 실행 대상에서 iPhone과 페어링된 Apple Watch를 선택합니다. `Jarvis` iPhone 앱을 실행하면 포함된 `JarvisWatch` 앱도 설치 대상으로 전달됩니다. Watch 앱이 자동 설치되지 않으면 iPhone의 Watch 앱 → **사용 가능한 앱**에서 JARVIS를 설치합니다.

## 첫 실행

첫 실행 시 다음 권한을 허용합니다.

- 마이크
- 음성 인식

`현재 브리핑` 또는 날씨 명령을 처음 실행할 때는 위치 권한도 허용합니다.

- 앱을 사용하는 동안 위치

연락처 이름으로 전화를 처음 실행할 때는 연락처 접근도 허용합니다. 전화번호를 직접 말하거나 입력하는 경우에는 연락처 권한이 필요하지 않습니다.

“한 번만 음성 대화하기”는 곧바로 명령을 듣습니다. 일반 iOS 앱은 Siri처럼 다른 미디어를 방해하지 않으면서 임의의 호출어를 상시 감지할 수 없으므로, 시스템 Siri 또는 음성 단축어가 호출을 담당합니다.

- “자비스”만 말해 호출: iPhone **설정 → 손쉬운 사용 → 음성 단축어**에서 JARVIS의 **자비스에게 말하기** 동작을 선택하고 호출 문구를 “자비스”로 등록합니다.
- 앱의 **백그라운드 호출 설정** 화면에서도 동일한 안내를 확인할 수 있습니다.

이 구조에서는 JARVIS가 백그라운드로 가면 앱의 마이크와 오디오 세션을 즉시 해제합니다. 시스템이 호출을 감지한 순간에만 JARVIS가 열려 명령을 듣습니다.

## 대화 AI 구조

지원되는 iOS 26 기기에서는 Apple Foundation Models를 임시 대화 엔진으로 사용합니다. 명령 판단, YouTube 실행, 사용자 설정 등은 앱이 직접 관리하며, 향후 `AIClient`만 교체해 직접 제작하거나 미세 조정한 온디바이스 모델로 이전할 수 있도록 분리했습니다.

명령은 다음의 제한된 두뇌 운영 흐름을 따릅니다.

1. `CommandRouter`가 알려진 명령을 빠르고 결정론적으로 분류합니다.
2. 분류되지 않은 자연어만 `AgentOrchestrator`가 온디바이스 모델에 구조화된 의도 후보를 요청합니다.
3. `CapabilityRegistry`가 허용된 기능인지 확인하고 필수 인자와 범위를 검증합니다.
4. 모든 실행 후보를 `SafetyPolicyEngine`이 위험도, 실행 출처, 긴급 안전 잠금 기준으로 다시 판단합니다.
5. 승인된 `AssistantIntent`만 Swift 실행기로 전달됩니다.

모델이 제안한 앱 열기·전화·길 안내 같은 중간 이상 위험 동작은 실행 전에 사용자의 확인을 받습니다. 알람, 장기 기억 변경, 자격 증명, 권한 및 안전 설정은 모호한 자연어에 대한 모델 추론으로 실행하지 않습니다. 지원되지 않는 기기에서는 기존 결정론적 명령과 기본 대화로 안전하게 돌아갑니다.

### 명령 이해 평가

날씨·일정·미디어뿐 아니라 YouTube, 재생목록, 전화, 앱 실행, 길 안내, 인터넷 검색, 음식점 추천, 알람, 기억과 후속 질문을 포함한 서로 다른 실사용 문장 339개를 `EvaluationCaseV2`로 관리합니다. 각 사례에는 정답 의도, 위험도, 입력 출처, 음성 인식 변형·띄어쓰기·후속 질문·대명사·주제 전환·모호성 태그가 기록되며 실패를 의도 분류·인자 추출·음성 변형·문맥·위험 오작동 등으로 구분합니다. 50개의 문장 문맥 시나리오와 별도의 50개 대화 상태 시나리오를 재생해 오래된 목적지·앱·승인 문맥 재사용, 보류 작업 교체, 취소, 만료와 재시도 소진을 검사합니다.

설정 → **명령 이해 평가**에서 전체·기능별·태그별 정확도, 음성 인식 변형 정확도, 평균·최장 분류 시간과 두 종류의 다단계 대화 성공률을 확인할 수 있습니다. 전체 정확도 95% 이상, 음성 인식 변형 90% 이상, 위험 오작동과 모호한 명령의 추측 실행 0건을 동시에 만족해야 통과합니다. **현재 결과를 평가 이력에 저장**하면 최대 20개의 이전 실행 중 하나를 골라 정확도·음성 변형·안전 지표 변화, 새 실패, 해결된 실패를 기기 안에서 비교합니다. 이전 단일 기준값은 처음 열 때 새 이력 형식으로 자동 이전됩니다. 저장 데이터에는 명령 원문이 아니라 집계와 실패 사례 ID만 포함됩니다.

### 음성 평가 문장과 일반 대화 평가

설정 → **음성 평가 문장 검토**에서 수집을 직접 켤 수 있습니다. 기본값은 꺼짐입니다. 전화·장소·알람·기억·검색 등 개인 정보가 들어갈 수 있는 명령은 수집 대상에서 제외하고, 제한된 읽기 전용 명령만 기기 안의 검토 대기 목록에 올립니다. 검토 대기 문장은 앱을 종료하면 사라지고, 사용자가 문장과 예상 명령을 확인해 승인한 것만 최대 200개까지 이 iPhone에 저장합니다. 승인 문장은 개별 또는 전체 삭제할 수 있습니다. 자동 필터만으로 완전한 익명성을 보장할 수 없으므로 승인 전 이름·장소 등 개인 정보가 없는지 확인해야 합니다. 이 평가는 음성 파형이 아니라 인식된 문장을 명령으로 분류하는 단계만 검사합니다.

**명령 이해 평가** 화면에는 별도 일반 대화 평가 데이터의 결과도 표시됩니다. 사실·의견·설명·비교·요약·일상 대화·모호한 질문과 최신 정보가 필요한 질문을 구분하고, 화면/음성 답변 형식과 URL 비낭독을 검사합니다. 이 자동 평가는 생성된 답변의 사실 정확성이나 유용성을 입증하지 않으며, 실제 모델 답변은 별도 사람 검토가 필요합니다.

### OpenAI 개인용 연결과 사용/비사용 모드

설정 → **OpenAI 연결 · 사용 모드**에서 개인 API 키를 입력하고 **키 저장 및 설정 적용**을 누른 뒤 **사용**을 선택합니다. 처음에는 비사용 모드이며 키 저장만으로 API 요청을 보내지 않습니다. 키는 잠금 해제 시 접근할 수 있는 이 iPhone 전용 Keychain에 보관하고 소스·UserDefaults·채팅·감사 기록에는 넣지 않습니다. 이 기능은 사용자가 선택한 개인용 직접 연결 방식입니다. 공용 키를 포함해 앱을 배포하려면 서버에 키를 보관하는 별도 중계 구조가 필요합니다. [OpenAI 공식 인증 지침](https://developers.openai.com/api/reference/overview#authentication)을 참고하세요.

사용 모드에서는 `gpt-4.1-mini`의 Responses API로 일반 대화와 웹 검색 결과 요약을 요청합니다. 기본 명령과 의미 기반 도구 후보 분류는 기존 기기 내 경로를 우선 사용합니다. 별도 동의 옵션인 **미해결 명령에 OpenAI 해석 사용**을 켠 경우에만 해결되지 않은 문장에 추가 분류 요청을 보냅니다. OpenAI는 기기 도구를 직접 호출하거나 알람·기억·안전 정책을 변경하지 않습니다. API 키 오류·요청 한도·네트워크 실패는 설정과 채팅의 API 상태에 표시하고 해당 요청을 로컬 엔진으로 돌립니다. 모델의 명시적 답변 거절은 로컬 모델로 재시도하지 않습니다.

**비사용**을 누르면 이후 API 호출을 막고 진행 중인 요청을 취소합니다. 새 명령·앱 백그라운드 전환·중지 시에도 진행 중인 대화 요청을 취소해 늦게 도착한 답변을 버립니다. 이미 서버가 처리한 요청은 취소해도 과금될 수 있습니다. 요청은 20초 연결 제한과 25초 리소스 제한을 사용하며 자동 재시도를 하지 않습니다. 기본 한도는 하루 30회, 응답 최대 400토큰이며 각각 최대 100회·800토큰까지 설정합니다. 실제 응답의 입력/출력 토큰을 앱에 집계하며 실패·취소 요청의 사용량은 OpenAI 대시보드에서 확인해야 합니다. 이 앱의 요청 한도는 계정 결제 한도를 대체하지 않습니다.

외부 전송은 사용자가 설정 화면에서 명시적으로 확인합니다. 현재 입력과 요약할 검색 내용 일부를 보내며, 최근 대화는 선택 시 최대 4턴과 제한된 요약만 보냅니다. 관련 장기 기억·사용자 프로필 전송은 별도 옵션이며 기본값은 꺼짐입니다. 모든 외부 입력은 `AssistantContextManager`에서 길이를 제한하고 참고 데이터로 구성합니다. 응답은 `store: false`로 요청하되, 이는 OpenAI 서비스의 모든 데이터 보관이 없어짐을 의미하지 않습니다. [공식 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)이 별도로 적용됩니다. 안전 잠금은 신규 외부 AI 설정과 새 클라우드 요청을 차단하며 사용 중지·키 삭제는 계속 가능합니다.

### 학습 결과 화면

설정 → **학습 결과**에서 사용자가 승인한 개인화 기억의 분류, 같은 명령 평가 버전에서 확인된 개선 분야와 해결된 실패 수, 누적 API 대화·검색 요약 응답 수를 확인합니다. 평가 개선은 이전/현재 결과를 **명령 이해 평가**에서 저장한 경우에만 비교합니다. 데이터 버전이 다르거나 새 실패·안전 회귀가 있으면 개선 성공으로 표시하지 않습니다.

현재 자체 모델의 가중치 학습·미세 조정 작업은 구현되어 있지 않으므로 해당 화면에는 실제 모델 학습을 아직 수행하지 않았다고 표시합니다. API 응답 수신이나 개인화 기억 저장을 모델 학습 완료로 기록하지 않습니다. API 결과 통계에는 원문과 키를 저장하지 않습니다.

### 길 안내

“강남역으로 안내 부탁해”처럼 이동 방식을 생략하면 대중교통 길찾기를 사용합니다. “차로”, “자가용으로”를 명시하면 네이버 지도 자동차 내비게이션으로 연결합니다. 목적지는 명령 해석과 외부 지도 실행 직전에 다시 검증하여 `강남역 역` 같은 중복 지명을 제거합니다. `하이디 라오`처럼 음성 인식이 상호명 사이에 공백을 넣어도 공백 제거 형태로 한 번 더 검색합니다. Apple 지도에 없는 국내 상호는 설정에 등록한 Google Places API로 추가 검색하고, 입력과 이름이 관련 없는 결과는 목적지로 자동 확정하지 않습니다. 지도 검색 결과가 하나면 바로 연결하고, 같은 이름의 지점이나 장소가 여러 곳이면 최대 5개의 `번호·장소명·지역`을 안내한 뒤 “2번”, “강남점”, “종로구” 같은 답으로 목적지를 확정합니다.

네이버 지도 공식 URL Scheme에서 자동차는 내비게이션 시작 액션을 제공하지만, 대중교통은 최적 경로 결과를 여는 `route/public` 액션만 제공합니다. 따라서 JARVIS는 최적 대중교통 결과까지 즉시 연결하며, 네이버 지도 내부의 ‘바로 안내시작’ 선택은 사용자가 눌러야 합니다.

### 다단계 대화 상태

여러 알람 중 선택, 장기 기억 저장 제안, 안전 승인은 `DialogueStateManager`가 하나의 활성 작업으로 관리합니다. 보류 상태는 2분 뒤 만료되고 잘못된 답변은 두 번까지만 다시 묻습니다. `DialogueInputResolver`는 현재 문장만으로 완성된 새 명령인지 먼저 판정하여, 새 명령이면 이전 작업을 취소하고 교체합니다. 이 판정에는 완료된 과거 명령의 목적지·연락처를 주입하지 않으므로 오래된 대상을 새 명령에 잘못 재사용하지 않습니다.

### 도구 실행 결과

`JarvisTests`의 iOS 시뮬레이터 통합 테스트는 실제 `AssistantViewModel`에 여러 텍스트 턴을 차례로 입력해 일정 후속 질문과 새 주제 전환을 검사합니다. 테스트에서는 오디오 출력만 비활성화하며 명령 라우팅, 안전 판단, 대화 상태와 응답 생성은 앱 경로를 그대로 통과합니다. 실제 마이크·TTS·외부 앱 전환의 단말 E2E는 별도의 실기 검증이 필요합니다.

음성 명령의 YouTube 목적지 조회와 알람 갱신·설정·수정·삭제, 날씨·캘린더 조회, 웹 검색은 공통 실행 조정기를 사용합니다. 날씨 위치 권한 거부와 조회 실패는 성공 결과와 구분합니다. 잠금 화면/App Intent의 알람 종료도 같은 안전 정책 및 실행 조정기를 거치며, 안전 잠금 중에는 위해를 줄이는 알람 정지만 허용됩니다.

외부 앱과 기기 기능은 `ToolExecutionResult`로 **검증된 완료**, **외부 앱에 요청 전달**, **권한 필요**, **추가 확인 필요**, **실패**, **결과 확인 불가**를 구분합니다. 동일한 도구의 중복 실행을 막고 제한 시간을 적용합니다. 알람·기억·음량처럼 상태를 변경하는 작업은 자동 재시도하지 않으며, 날씨·일정·검색·음식점·목적지 후보 조회처럼 멱등인 읽기 작업만 일시적인 통신 오류에 한해 한 번 재시도합니다. 권한 거부, 확인 필요와 영구 실패는 구분해 쉬운 문장으로 안내합니다. YouTube·전화·지도·앱 실행은 iOS가 요청을 받은 것까지만 확인할 수 있으므로 실제 재생·통화·경로 시작이 완료됐다고 표현하지 않습니다.

Apple Foundation Models는 초기 추론 엔진이지, JARVIS 모델을 자동으로 학습시켜 주는 교사는 아닙니다. 개인화는 사용자가 명시적으로 동의한 설정과 장기 기억을 앱이 별도로 관리해 요청 문맥에 제공하는 방식입니다.

일반 대화는 사실·의견·설명·비교·요약·일상 대화로 분류합니다. 화면에는 전체 답변과 출처를 보여주고, 음성은 URL과 마크다운을 제거한 결론 중심 2~4문장만 읽습니다. `최신`, `속보`, `현재 가격`, `실시간`과 같은 시점 의존적 질문은 정적인 온디바이스 지식으로 추측하지 않고 인터넷 검색으로 전환합니다.

설정 → **나의 정보 및 AI 스타일**에서 저장한 정보는 iPhone Keychain에만 보관되며, Apple 온디바이스 AI에게 보내는 다음 요청부터 참고 정보로 함께 제공됩니다.

`AssistantContextManager`는 앱이 실행되는 동안 최근 12개의 사용자·자비스 대화를 원문으로 기억합니다. “그거”, “거기”, “두 번째 것”, “더 자세히” 같은 실제 후속 표현이 나온 경우에만 의미 분석기에 최근 문맥을 제공합니다. 목적지·앱·검색어처럼 현재 문장에 새 대상이 명시되면 이전 같은 계열 명령보다 새 대상을 우선하여 과거 문맥에 고정되는 현상을 막습니다. 12개를 넘은 오래된 대화는 최대 8개의 짧은 요약으로 압축하며, 장기 기억도 현재 명령과 관련 있는 항목을 최대 8개만 골라 문맥이 무한히 커지지 않게 합니다. 이 단기 메모리는 장기 저장하지 않으며 앱을 완전히 종료하면 초기화됩니다.

“나는 매운 음식을 좋아해. 기억해줘”, “매운 음식 관련 기억을 잊어줘”, “기억 목록 보여줘”처럼 장기 기억을 관리할 수 있습니다. 같은 개인 정보가 대화에서 반복되면 JARVIS가 장기 저장 여부를 먼저 물으며, 동의 전에는 저장하지 않습니다. 저장된 항목은 설정 → **장기 기억 관리**에서 직접 추가·수정·삭제할 수 있고 iPhone Keychain에 보관됩니다.

각 기억은 분류, 출처, 저장·수정 시각, 중요도, 선택적 만료일과 마지막 참고 시각을 기록합니다. 만료된 기억은 AI 문맥에서 제외되고, 중복 기억은 병합하며 서로 충돌할 가능성이 있는 기억은 설정에 표시합니다. 민감한 정보는 저장 전에 별도로 확인하며, “왜 이렇게 답했어?”라고 물으면 직전 답변에 참고한 기억을 설명합니다.

설정 → **능동 제안 설정**에서 **제안 안 함**, **버튼·명령으로 실행**, **안전한 제안 자동 실행** 중 하나를 선택할 수 있습니다. 자동 모드는 날씨·일정 조회처럼 안전 정책이 `informational`로 분류한 읽기 전용 작업만 실행합니다. 연락·삭제·예약·외부 앱 실행은 자동 모드에서도 명시적 승인을 받고 `SafetyPolicyEngine`을 다시 통과합니다. 같은 제안은 24시간 동안 반복하지 않습니다.

## 안전 정책

모델의 답변과 기기 작업 실행 권한을 분리했습니다. 언어 모델은 명령을 이해하거나 작업을 제안할 수 있지만, 실제 전화·앱·지도·YouTube 실행과 데이터 변경은 Swift로 구현된 `SafetyPolicyEngine`의 결정을 반드시 통과해야 합니다. 모델이나 인터넷 검색 결과, 저장된 기억은 이 정책을 변경하거나 우회할 수 없습니다.

설정 → **안전 및 실행 기록**에서 긴급 안전 잠금을 켜면 외부 앱 실행과 데이터 변경이 즉시 차단됩니다. 잠금 중에도 날씨·시간·일정 조회와 현재 울리는 알람 정지, 미디어 정지, 음량 조절은 사용할 수 있습니다. 모든 알람 또는 모든 장기 기억 삭제처럼 되돌리기 어려운 작업은 한 번 더 명시적으로 확인합니다.

실행 기록에는 작업의 일반적인 종류, 위험도, 허용·차단 결과만 저장합니다. 연락처 이름, 목적지, 명령 원문, 장기 기억 내용 같은 개인정보는 기록하지 않습니다.

음성 명령이 불완전하거나 인식에 실패하면 안내 응답을 한 뒤 즉시 다시 듣습니다. 연속 인식 오류가 발생하는 경우에는 무한 재시도를 피하기 위해 오류 상태로 전환합니다.

현재 기능과 Apple 온디바이스 AI를 점검할 수 있도록 [기본 명령·대화 200선](Documentation/JARVIS_COMMANDS_200.md)을 마련했습니다. 이 목록은 실제 iPhone 회귀 테스트와 향후 개인화 데이터 설계의 초기 기준으로 사용합니다.

## 인터넷 검색 설정

1. [Tavily 대시보드](https://app.tavily.com/home)에서 계정을 만들고 API 키를 발급합니다.
2. JARVIS 우측 상단 톱니바퀴 → **인터넷 검색**에 API 키를 저장합니다.
3. “인터넷에 오늘 AI 뉴스를 검색해서 알려줘”처럼 명령합니다.

검색은 `basic` 단계의 단일 REST 요청을 사용하며, 결과 답변만 TTS로 읽습니다. 출처 제목과 URL은 채팅 말풍선 아래에 누를 수 있는 링크로만 표시하여 음성으로 읽지 않습니다. API 키는 소스 코드가 아닌 iPhone Keychain에 저장됩니다. 개인용 배포에서는 이 방식으로 충분하지만, App Store에 공개할 때는 API 키를 앱에 배포하지 않고 본인의 중계 서버에 보관해야 합니다.

## JARVIS 음성 선택

JARVIS 설정 → **자비스 목소리**에서 현재 iPhone에 설치된 한국어 음성을 직접 선택하고 미리 들을 수 있습니다. `자동 선택`은 고품질 남성 음성을 우선하며, 직접 선택한 음성은 다음 한국어 응답부터 적용됩니다.

음성 응답 직전에는 마이크 입력 세션을 완전히 종료하고 짧은 전환 대기 후, 녹음 세션을 재사용하지 않는 iOS 시스템 관리 출력 세션에서 TTS를 재생합니다. 합성이 시작되지 않거나 시스템에 의해 취소되면 합성기를 새로 만들고 기본 한국어 음성으로 한 번 재시도하며, 재시도도 실패하면 화면이 계속 `말하는 중`에 멈추지 않도록 응답 상태를 종료합니다.

추가 음성은 iPhone **설정 → 손쉬운 사용 → 읽기 및 말하기 → 음성 → 한국어**에서 내려받은 뒤 JARVIS 설정 화면을 다시 열어 목록을 갱신합니다.

## YouTube 첫 영상 실행 설정

1. Google Cloud Console에서 프로젝트를 생성합니다.
2. **YouTube Data API v3**를 활성화합니다.
3. 자격 증명에서 API 키를 생성합니다.
4. 가능하면 iOS 앱 `com.minhyuc.jarvis`와 YouTube Data API v3로 키 사용을 제한합니다.
5. JARVIS 우측 상단의 톱니바퀴 → **YouTube 첫 영상 실행**에 키를 저장합니다.

API 키는 소스 코드나 Git에 저장되지 않고 해당 iPhone의 Keychain에만 저장됩니다.

## YouTube 내 재생목록

JARVIS는 Google OAuth의 YouTube 읽기 전용 권한을 사용해 현재 계정이 직접 만든 재생목록만 가져옵니다. 계정 연결을 켜려면 최초 한 번 다음 설정이 필요합니다.

1. Google Cloud Console에서 YouTube Data API v3를 활성화합니다.
2. OAuth 동의 화면을 설정하고, 테스트 모드라면 본인의 Google 계정을 **테스트 사용자**로 추가합니다.
3. **iOS 애플리케이션** 유형의 OAuth 클라이언트를 만듭니다.
4. 번들 ID는 `com.minhyuc.jarvis`로 입력합니다.
5. [Info.plist](Jarvis/Info.plist)의 `GIDClientID`를 발급받은 iOS 클라이언트 ID로 바꿉니다.
6. 같은 파일의 `com.googleusercontent.apps.REPLACE_ME`를 Google Cloud에 표시된 **iOS URL scheme** 값으로 바꿉니다.
7. 앱을 다시 실행한 뒤 JARVIS 설정 → **내 재생목록 관리** → **Google 계정 연결**을 누릅니다.

연결하면 `playlists.list` API의 `mine=true`로 직접 만든 재생목록을 동기화합니다. “유튜브에서 운동 재생목록 틀어줘” 또는 “출근 플레이리스트 재생해줘”라고 명령할 수 있습니다. 타인이 만든 저장 재생목록과 나중에 볼 동영상은 동기화 대상이 아닙니다.

## iPhone 현재 브리핑

별도의 단축어 없이 JARVIS가 현재 위치의 Open-Meteo 날씨와 앱 내부의 JARVIS 전용 캘린더를 읽습니다. Apple 캘린더와 동기화하지 않으며, 홈 화면의 **캘린더 관리**에서 일정을 추가·확인·수정·삭제할 수 있습니다. 캘린더는 달을 아래위로 자연스럽게 연속 스크롤하며 일정을 확인할 수 있고, 12월과 1월 사이에서도 다음·이전 연도로 자동 연결됩니다. 날짜마다 일정 제목을 최대 2개와 추가 일정 개수로 요약하며, 스크롤한 위치에 맞춰 상단 연도·월 표시도 자동으로 바뀌어집니다. 연도와 월은 서로 구분된 버튼으로 표시되며 각각 눌러 휠 선택기에서 먼 날짜로 빠르게 이동할 수 있습니다. 날짜를 누르면 별도의 24시간 일간 화면으로 이동하며, 시간표를 위아래로 스크롤하고 빈 시간을 눌러 해당 시간에 일정을 바로 등록할 수 있습니다. 등록된 일정은 눌러 수정하거나 확인 후 삭제할 수 있습니다. 상단 돋보기는 연도·월과 월 스크롤을 표시하지 않는 독립 검색 화면을 열며 제목·장소·메모를 검색합니다. 검색 결과에는 일정의 날짜와 시간이 함께 표시되고, `지난 일정`과 `앞으로 있을 일정`을 선택해 각각 날짜가 이른 순서로 확인할 수 있습니다. 검색 결과를 누르면 편집 창을 열지 않고 월 캘린더로 돌아가 해당 일정의 날짜를 선택하고 화면에 표시합니다. 검색어 지우기와 검색 화면 닫기는 기존 캘린더의 월 위치를 변경하지 않습니다. 하루 종일, URL, 매일·매주·매월·매년 반복과 사전 알림도 기존과 동일하게 사용할 수 있습니다. 명령에 필요한 정보만 응답합니다.

일정 시각에는 로컬 알림 팝업과 선택한 JARVIS 음성으로 일정 제목을 안내합니다. 일정 편집에서 **야외 일정**을 켜면 앱이 활성화될 때 Open-Meteo의 해당 시각 예보로 알림을 갱신하고, 기온·강수 확률과 우산 안내를 함께 읽습니다. iOS는 로컬 알림이 울리는 순간 일반 앱의 네트워크 조회를 허용하지 않으므로, 장기간 앱을 열지 않은 경우에는 마지막으로 받아둔 예보 또는 날씨 확인 안내가 사용됩니다.

현재 운영 캘린더는 iPhone에 저장되는 개인용 로컬 캘린더입니다. 별도 동기화 DB로 수동 백업·내보내기·가져오기를 제공하지만 운영 캘린더와 실제 알림 예약의 양방향 자동 반영은 아직 없습니다. 공유 캘린더, 참석자 초대·응답, 첨부 파일도 포함하지 않습니다.

- “현재 브리핑”: 시각, 날씨, 강수 확률, 일정을 함께 안내
- “오늘 날씨 알려줘”: 현재·최고·최저 기온과 강수 확률만 안내
- “현재 기온 알려줘”: 현재 기온만 안내
- “우산 필요해?”: 강수 확률을 기준으로 우산만 안내
- “오늘 일정 알려줘”: 오늘 캘린더 일정만 안내
- “다음 일정 알려줘”: 현재 시각 이후의 가장 가까운 일정만 안내
- “지금 몇 시야”: 기기의 현재 시각만 안내

- 시간대에 맞춘 아침·오후·저녁 인사와 현재 시각
- 오늘 최고·최저·현재 기온
- 오늘 강수 확률과 우산 안내
- 오늘 캘린더 일정 또는 일정 없음 안내

날씨 조회에는 API 키나 WeatherKit entitlement가 필요하지 않습니다. 따라서 개인용 무료 개발 프로비저닝으로도 앱에 서명할 수 있습니다. 날씨 데이터는 [Open-Meteo](https://open-meteo.com/)에서 가져옵니다.

## 현재 위치 맛집 추천 설정

1. Google Cloud Console에서 프로젝트의 결제 계정을 연결합니다.
2. **Places API (New)**를 활성화합니다.
3. 이 기능만을 위한 별도의 API 키를 만듭니다.
4. API 제한은 Places API (New)로, iOS 앱 제한은 현재 Bundle Identifier로 설정합니다.
5. JARVIS 설정 → **현재 위치 맛집 추천**에 API 키를 저장합니다.

“근처 맛집 추천해줘”, “평점 좋은 한식 맛집 추천해줘”, “가까운 초밥집 찾아줘”처럼 명령할 수 있습니다. 결과는 현재 위치 5km 이내의 후보 중 평점과 리뷰 수를 함께 반영한 가게 3곳과 대표 메뉴만 간결히 안내합니다. 이어서 “다른 집 추천해줘”라고 하면 이미 안내한 가게를 제외하고 다음 3곳을 추천합니다. 대표 메뉴를 확인할 수 없으면 `대표 메뉴: 확인 불가`로 표시합니다. API 키는 소스나 Git에 저장되지 않고 iPhone Keychain에만 보관됩니다.

## Apple Watch YouTube 제어

Watch용 JARVIS의 **재생 제어**를 누르면 시스템의 지금 재생 중 화면이 열립니다. iPhone에서 YouTube 영상이나 음악이 이미 재생 중일 때 재생·일시정지·이전·다음과 Digital Crown 음량 조절을 사용할 수 있습니다.

현재 Watch 앱에는 요청대로 브리핑 기능을 넣지 않았으며 YouTube·미디어 제어만 제공합니다.

Apple Watch와 iPhone의 실제 잠금 상태를 제3자 앱이 조회하거나 잠금을 우회할 수는 없습니다. 명령을 받은 기기에서 시스템이 허용하는 동작을 실행하며, 새 YouTube 영상을 iPhone에서 여는 작업은 iPhone이 잠겨 있으면 잠금 해제가 필요합니다. 이미 재생 중인 미디어는 잠긴 iPhone에서도 Watch의 지금 재생 중 화면으로 제어할 수 있습니다.

## 미디어 중지·볼륨·알람

“노래 꺼줘”, “유튜브 재생 멈춰줘”로 현재 재생을 중지하려면 단축어 앱에서 최초 한 번 다음을 설정합니다.

1. `재생/일시 정지` 동작을 추가하고 동작을 `일시 정지`로 선택합니다.
2. 단축어 이름을 정확히 `미디어 일시 정지`로 저장합니다.

“볼륨 40퍼센트로 해줘”, “볼륨 올려줘”, “음소거해줘”를 지원합니다. 증감 명령은 10퍼센트포인트 단위로 동작합니다.

“내일 오전 7시 30분에 알람 맞춰줘”, “10분 뒤에 알람 울려줘”처럼 `알람/알림/타이머` 설정을 명시하면 시스템 알람음을 사용합니다. “10분 뒤에 불 끄라고 해줘”, “라면 물 꺼야 하니까 3분 뒤에 알려줘”처럼 자연어로 말하면 시스템 알람음 대신 선택한 JARVIS TTS 음성이 안내 문구를 읽습니다. 따옴표로 지정한 문구는 그대로 사용합니다.

메인 화면의 **알람 관리**에서 두 유형을 함께 확인하고 추가, 편집, 활성화, 비활성화, 개별/전체 삭제할 수 있습니다. 시스템 알람은 주황색, JARVIS TTS 알림은 파란색과 유형 배지로 구분합니다. “내 알람 보여줘”, “라면 알람 취소해줘”, “오후 2시 알람을 오후 3시로 미뤄줘”도 지원합니다.

알람이 울리는 동안 JARVIS 앱을 사용 중이면 “알람 꺼줘”로 중지할 수 있습니다. iPhone이 잠긴 상태에서는 “Siri야, JARVIS 알람 꺼줘”라고 말하거나 iOS 26 AlarmKit 잠금 화면의 **중지** 버튼을 사용합니다. 앱이 잠금 상태에서 독자적으로 마이크를 항상 듣지는 않으므로 “JARVIS” 호출어만으로는 실행되지 않습니다.

오전·오후를 생략한 1~12시는 같은 숫자의 오전/오후 후보 중 현재로부터 가장 가까운 미래를 선택합니다. `오전`, `오후`, `오늘`, `내일` 등을 직접 말하면 그 표현을 우선합니다.

시스템 알람은 iOS 26.0 이상에서 AlarmKit, 이전 iOS에서 기본 소리의 로컬 알림을 사용합니다. JARVIS TTS 알림은 선택한 음성으로 30초 미만의 CAF 파일을 미리 생성하여 로컬 알림음으로 재생합니다. TTS 생성에 실패해도 일반 시스템 소리로 대체하지 않습니다. 단, 무음 모드·집중 모드·알림 권한에 따라 TTS 소리도 제한될 수 있습니다.

## 다른 앱 실행

“사파리 열어줘”, “지도 실행해줘”처럼 말하면 시스템 URL로 바로 엽니다. 직접 URL이 정의되지 않은 앱은 단축어 앱에서 `앱이름 열기`라는 단축어를 만들고 **앱 열기** 동작에 원하는 앱을 지정합니다.

예를 들어 카카오톡은 단축어 이름을 `카카오톡 열기`로 저장한 뒤 JARVIS에게 “카카오톡 열어줘”라고 말합니다. 앱 설정 → **다른 앱 실행 연결**에서 안내를 확인할 수 있습니다.

## 전화 연결

“민수한테 전화해줘”, “010-1234-5678로 전화해줘”처럼 말하면 연락처 또는 전화번호를 확인해 시스템 전화 화면을 엽니다. 음성 인식된 이름이 연락처와 완전히 같지 않아도 공백·문장부호를 제거하고 유사도를 비교해 명확한 후보로 연결합니다. 유사한 후보가 여러 명이면 잘못된 통화를 막기 위해 이름을 다시 묻습니다. 연락처에 번호가 여러 개 있으면 휴대전화·iPhone 번호를 우선합니다.

“민수한테 스피커폰으로 전화해줘”도 전화 연결 명령으로 인식하지만, 일반 이동통신 통화의 스피커 상태는 Phone 앱이 소유합니다. iOS 공개 API로 다른 앱이 이를 강제로 켤 수 없으므로 통화가 시작된 후 통화 화면의 **스피커** 버튼을 눌러야 합니다.

## 뒷면 탭 연결

앱을 한 번 실행한 후 단축어 앱에서 JARVIS의 “자비스에게 말하기” 동작이 나타나는지 확인합니다.

1. 설정 → 손쉬운 사용 → 터치 → 뒷면 탭으로 이동합니다.
2. 이중 탭 또는 삼중 탭을 선택합니다.
3. “자비스에게 말하기” 단축어를 지정합니다.

액션 버튼을 지원하는 iPhone은 설정 → 액션 버튼 → 단축어에서 같은 동작을 선택할 수 있습니다.

## 구조

```text
Jarvis/                  iOS 앱과 음성/UI 구현
JarvisWatch/             watchOS YouTube·미디어 재생 제어 UI
Shared/                  iPhone 날씨·캘린더 브리핑 구현
Sources/JarvisCore/      플랫폼 독립 명령 라우터
Tests/JarvisCoreTests/   명령 라우터 단위 테스트
Package.swift            핵심 로직을 별도로 테스트하기 위한 패키지
Jarvis.xcodeproj/        iOS 앱 프로젝트
```

`AIClient`는 Apple Foundation Models, 기본 로컬 응답, 향후의 자체 모델을 동일한 앱 로직에 연결하기 위한 경계입니다. 알려진 명령은 `CommandRouter`에서 AI 없이 처리하므로 모델 상태와 관계없이 빠르게 실행할 수 있습니다.

## 테스트

Xcode가 설치되고 활성화된 환경에서는 다음 명령으로 핵심 로직을 테스트할 수 있습니다.

```sh
swift test
```

앱 빌드는 다음과 같이 확인할 수 있습니다.

```sh
xcodebuild -project Jarvis.xcodeproj \
  -scheme Jarvis \
  -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  build
```

사용 가능한 시뮬레이터 이름은 Xcode 설치 버전에 따라 다릅니다.

## 현재 제한

- Xcode 26.5의 iPhoneOS·watchOS SDK를 사용한 통합 빌드가 성공했습니다.
- 핵심 명령·두뇌 오케스트레이션·339개 V2 명령 평가·50개 문장 문맥 시나리오·50개 대화 상태 시나리오·평가 이력 비교·도구 실행 결과와 제한 재시도·문맥 선택·단기·장기 기억 제안·안전 정책·목적지 정규화·이름 유사도·URL 빌더 단위 테스트를 자동 검증합니다.
- `지금 나오는 노래가 뭐야?`라고 말하면 iOS의 `노래 찾기` 단축어를 실행하고, 인식 결과를 다시 JARVIS로 받아 안내합니다.
- 이 방식은 무료 Personal Team에서도 사용할 수 있으며 JARVIS 타겟의 ShazamKit entitlement가 필요하지 않습니다. 단축어 이름은 정확히 `노래 찾기`여야 합니다.
- 백그라운드 호출은 JARVIS의 상시 녹음이 아니라 iOS의 Siri·음성 단축어에 의존합니다.
- Watch의 YouTube 제어는 시스템 `지금 재생 중`을 사용하며, JARVIS가 YouTube의 비공개 재생 API를 직접 조작하지는 않습니다.
- iPhone과 Watch의 잠금 상태를 앱이 조회해 실행 기기를 강제로 선택하는 것은 지원되지 않습니다.
- 내장 App Shortcut은 앱 설치·업데이트와 함께 자동 갱신되지만, 음성 단축어 호출 문구와 뒷면 탭 연결은 iOS 보안상 사용자가 최초 한 번 직접 선택해야 합니다.

## 명령 자동 학습 연습 · 개별 승인 · 대기 결과 30개

- **설정 → OpenAI 연결 → 학습 결과 → 명령 자동 학습 연습**에서 시작합니다. 한 번 누르면 10개 연습 슬롯을 만들고 OpenAI 생성 1회 + 별도 교사 검토 1회씩 최대 20회 요청을 보냅니다. 시작 전에 외부 전송과 비용을 확인하며 기존 사용/비사용 모드·하루 한도·안전 잠금을 유지합니다. 가중치 학습이나 미세 조정은 수행하지 않습니다.
- 사용 횟수 집계는 기본 꺼짐이며 별도 동의 후 **지원되는 기능별 횟수만** 기기에 저장합니다. 실제 대화 원문·연락처·전화번호·목적지·검색어는 집계하지 않습니다. 자주 쓰는 상위 기능에 대응하는 고정 합성 예제를 변형하며, 집계가 없으면 기본 예제를 씁니다. 현재 날씨·일정·시간·브리핑·노래 식별·미디어 정지·볼륨·주변 장소·가상 YouTube 검색·가상 길 안내 예제 등 16개 기준을 지원합니다. 알람·기억 변경·자격 증명·권한·안전 제어는 제외합니다.
- 학생은 **CommandRouter → 기기 내 모델/기본 분류기 → CapabilityRegistry**와 기존 승인 예제를 사용합니다. OpenAI를 학생 대신 호출하지 않고 교사로만 사용하며, 실제 도구·전화·지도·알람 등은 실행하지 않습니다. Apple 모델 미지원 기기에서는 기본 분류기 연습임을 화면에 표시합니다.
- 결과에서 기본 예제·변형 문장·변형 방법·고정 기준·JARVIS 최초 판단·OpenAI 교사 판단과 근거·자체 확신 수치·실패/중단 원인·사용자 결정 시각을 각각 확인합니다. 교사의 자체 확신은 실제 정확도가 아니며, 생성 모델과 검토 모델이 같은 모델이므로 독립적인 정답 보증도 아닙니다.
- **적용**을 개별 승인한 문항만 실제 명령 해석 예제로 활성화합니다. **폐기**는 승인 목록에 넣지 않으며 이미 적용된 문항이면 적용을 제거합니다. 연습 실행·결과 열람만으로는 어떤 문항도 적용되지 않습니다. 적용·폐기 이력은 검토용이며 폐기된 데이터는 명령 이해에 사용하지 않습니다. 적용은 API를 꺼도 기기에서 사용 가능하며 별도의 전체 사용 토글·개별 철회·전체 삭제를 지원합니다.
- 적용은 등록된 고정 예제와 교사 해석이 정확하게 일치한 경우만 허용합니다. 기존 라우터가 다른 의도로 처리하는 문장은 사용자 승인으로 덮어쓰지 않고 코드 수정 필요로 표시합니다. 취소·부정·대상 변경 문항과 미완료 결과는 적용하지 않습니다. 일치 문장 조회는 공백 정리·영문 소문자화만 수행하며, 구두점 제거·유사도·접두사 확장·새 대상 추측은 하지 않습니다. 따라서 새 표현 전체를 일반화해 학습하는 기능은 아닙니다.
- 승인된 해석은 여전히 `semanticModel` 출처로 중앙 안전 정책을 거칩니다. 길 안내 같은 중간 위험 동작은 실행 직전에 목적지와 이동수단을 확인받습니다. 학습 적용 승인은 실제 도구 실행 승인이 아닙니다. 철회·설정 변경 시 진행 중인 명령과 보류 승인을 취소합니다.
- 목적지·YouTube 검색 대상·볼륨 수치는 문항에 실제로 포함되어 있어야 합니다. 대상이 빠진 요청이나 “그거”, “거기로” 같은 문맥 의존 표현에 합성 예제의 대상을 영구 고정하지 않습니다. 그러한 결과도 검토·폐기할 수 있지만 적용은 차단합니다.
- **사용자 결정 대기 결과는 최대 30개**입니다. 실패·중단·대기 문항도 선택 전에는 이 공간을 사용하며 자동 삭제하지 않습니다. 적용 또는 폐기하면 그 문항은 대기 수에서 제외되어 새 결과를 받을 공간이 생깁니다. 다음 실행에는 10칸이 필요하므로 21~30개가 대기 중이면 먼저 결과를 처리해야 합니다. 완전히 검토한 묶음은 최근 10회까지 이력으로 남기고, 승인 예제는 별도로 최대 100개 유지합니다. 적용 후 철회해도 과거 검토 문항이 다시 대기 공간을 차지하지 않습니다.
- 취소·앱 종료·API 실패 시 미완료 문항은 실패/중단으로 보존하고 완료로 세지 않습니다. 앱 종료 후 자동 재개하거나 자동 유료 재시도하지 않습니다. 빈 슬롯 부족·하루 요청 한도 부족·비사용 모드에서는 API 호출 전에 시작을 막습니다. 이 기능은 개인용 직접 API 연결이며 앱이 백그라운드에서 무기한 학습하는 작업이 아닙니다.

## 실제 답변 평가·정정 검토와 주변 장소 대화

- 설정 → OpenAI 연결 → 학습 결과 → **실제 답변 평가·정정 검토**에서 수집·해석 옵션을 명시적으로 승인합니다. 두 옵션 모두 기본 꺼짐입니다. OpenAI 비사용·긴급 안전 잠금·하루 요청 한도를 우회하지 않습니다.
- 정정 수집을 켜면 “그게 아니라”, “잘못 이해했어”, “틀렸어” 등을 직전 질문·답변과 묶어 **메모리 안의 후보**로만 준비합니다. 자동 익명화나 자동 정답 판정을 보장하지 않습니다. 개인정보를 직접 지우거나 수정한 뒤 저장한 항목만 기기에 남습니다. 후보 10개, 승인 전 검토 자료 100개, 평가 이력 10회로 제한합니다. 개별 삭제·전체 삭제·수집 중지를 지원합니다.
- 저장한 자료별로 전송·비용 확인 후 OpenAI 수정안을 요청할 수 있습니다. 수정안은 검색으로 검증된 사실이 아니라 **검토 제안**입니다. 사용자가 사실을 확인하고 승인 → 동일 질문에 승인 참고 자료를 적용한 API 재응답 → 사용자 재검토 완료 순서로만 “검토·재검증한 답변 개선”에 집계합니다. 설정의 **학습 결과 → 모델 학습 상태**에서 질문과 검증 시각을 확인할 수 있습니다. 이는 자체 모델 가중치 학습이나 일반화 성공이 아닙니다.
- 검증 완료된 수정안은 수집·참고 옵션이 켜진 동안 **동일 질문의 일반 대화**에만 참고합니다. 내용이 충돌하면 선택하지 않으며, 명령 분류·도구 실행·권한·안전 판단에는 사용하지 않습니다. 삭제·중지 시 참고를 중단하고 이전 요청의 늦은 답변도 폐기합니다. 이미 전송된 자료를 외부 서버에서 회수하는 기능은 아닙니다.
- 실제 답변 평가는 고정 합성 질문 8개·총 13턴을 실제 API로 생성합니다. 버튼과 별도 확인 후에만 비용이 발생하는 요청을 시작합니다. 기존의 예시 답변 형식 검사와 다릅니다. 자동 키워드·길이 검사는 보조 지표이고 정확성·문맥·재질문·불확실성은 **사용자 평가**로 기록합니다. 동일 버전·질문·기준으로 검토 완료된 이전 실행과 비교해 개선과 퇴보를 함께 표시합니다. 미완료·미검토 결과를 성공으로 표시하지 않습니다. 보완 평가가 있는 항목은 추가 자료가 필요하다고 제안하지만 스스로 전송·학습·반복 과금하지 않습니다.
- 추가 명령 해석은 CommandRouter와 로컬 의미 해석이 해결하지 못할 때만 OpenAI가 제한된 JSON 후보를 제안합니다. Swift에서 허용 기능·인자·형식을 검증하고 기존 안전 정책을 적용합니다. 알람·기억 변경·자격 증명·권한·안전 제어는 일반 의미 해석에서 제외합니다.
- “근처 마트가 어떤 게 있어?” → “두 번째 마트 영업 중이야?” → “거기로 안내해줘” → “자가용으로”처럼 이어서 사용할 수 있습니다. 마트·약국·병원·주차장·카페를 지원하며 주변 5km에서 직선거리 기준 최대 3개 후보를 보여줍니다. 검색 식별자·주소·좌표를 단기 대화에 함께 유지합니다. 후보와 이동수단이 불명확하면 한 번에 하나씩 묻고, 다른 주제·취소·120초 만료·재시도 초과 시 버립니다.
- 주변 검색은 위치 권한을 필요할 때 요청합니다. 기존 Google Places 키가 있으면 Nearby Search를 사용하고 실패하거나 키가 없으면 Apple 지도 POI 검색으로 대체합니다. Google 필드에는 현재 영업 정보를 포함하므로 계정 설정에 따라 별도 Places 비용이 발생할 수 있습니다. Apple 검색이나 누락·오래된 영업 정보는 “확인하지 못했습니다”로 안내합니다. 출처 링크는 채팅에만 표시하며 읽지 않습니다. 거리·순서는 실제 이동시간이나 최단 경로 보장이 아닙니다.
- 길 안내는 확인한 좌표를 네이버 지도에 **전달**합니다. 안내 시작·최적 경로 선택 완료를 JARVIS가 검증했다고 주장하지 않습니다. 모델 제안·백그라운드의 중간 위험 실행은 별도 승인을 유지합니다.
- 개발 테스트는 가짜 API·지도 응답을 사용하므로 과금하지 않습니다. 실제 기기의 위치·영업 정보·네이버 지도 전환과 실제 모델 답변 품질은 사용자 환경에서 별도 확인해야 합니다.

## 다음 권장 단계

### 개인 비서 4~6단계 · 생활 흐름·기억·상황 제안

- 기존 주변 검색→후보 선택→지도 전달, 알람 수정·취소, 웹 답변의 화면 출처/음성 요약 분리를 유지합니다. 지도 최적 경로·실제 영업 여부는 확인한 범위를 넘어 주장하지 않습니다.
- 음성·채팅에서 `내일 오후 3시 회의 일정 등록해줘`, `회의 일정을 내일 오후 4시로 옮겨줘`, `회의 일정 취소해줘`, `내일 일정 알려줘`를 지원합니다. 초기 음성 문법은 오늘·내일과 명시적인 시각 중심입니다. 날짜·오전/오후가 빠지면 한 번에 하나씩 질문하며 지난 시각은 다음 날로 몰래 변경하지 않습니다. 제목은 따옴표로 지정할 수도 있습니다. 임의 날짜·반복 규칙·장소·세부 편집은 기존 캘린더 화면을 사용합니다.
- 음성 일정 변경은 저장·삭제 직전에 날짜·시간대·제목을 개별 확인합니다. 같은 제목의 일정은 번호로 선택하고, 겹치는 일정을 표시·안내합니다. 확인 중 대상/시간대/겹치는 일정이 바뀌면 재요청해야 합니다. 앱 캘린더 저장도 충돌 확인과 중앙 안전 정책을 거칩니다. 반복 일정의 음성 변경은 범위를 추측하지 않고 캘린더 화면에서 수정하도록 안내합니다.
- 일정 저장과 알림 예약은 별개로 검증합니다. 알림 권한·예약 실패 시 부분 완료를 설명합니다. iOS의 알림·잠금·집중 모드와 사전 합성 음성 제약은 그대로 적용됩니다.
- 장기 기억은 명시적 입력·저장 승인만 반영합니다. 정확히 같은 내용만 병합하며 유사 문장은 자동 덮어쓰지 않습니다. 충돌 가능성이 있는 기억은 답변 문맥에서 제외하고 설정에서 유지할 기억과 삭제할 관련 기억을 직접 선택·확인합니다. 민감정보는 추가·수정 모두 별도 확인합니다. 최대 100개를 넘으면 오래된 기억을 몰래 삭제하지 않고 추가를 거절합니다.
- 삭제·수정 전 내용의 SHA-256 해시·시각을 최대 1,000개 보관하여 같은 내용의 재제안을 줄입니다. 익명화 보증이나 모든 유사 표현의 차단은 아닙니다. 명시적인 재저장 요청은 허용합니다. 표식과 기억은 기기의 Keychain에 보관하며 이전 배열 포맷과 호환합니다. 저장 실패 시 메모리 상태도 되돌립니다.
- 기억 수정·삭제 시 단기 문맥과 이전 참고 기억을 초기화하고 진행 중 기억 기반 답변도 취소합니다. 관련 없는 기억·만료·미해결 충돌은 사용하지 않습니다. 기억은 실행 승인이나 안전 정책으로 취급하지 않습니다.
- 기존 제안 설정을 재사용합니다. **자동 모드: 정보 안내/낮은 위험은 자동 실행, 보통 위험은 확인, 높은 위험 제안은 승인 여부와 무관하게 차단**합니다. 직접 사용자 요청의 기존 확인 정책과 분리합니다. 기억 저장에는 자동 모드에서도 명시적 동의가 필요하고 긴급 잠금이 우선합니다. 버튼·명령 모드는 제안만 표시하고, 꺼짐 모드는 제안하지 않습니다.
- 날씨 조회 뒤 실제 Open-Meteo 수치로 조언을 만듭니다. 최대 강수 확률 40% 이상이면 우산, 전날 최고 기온 예보보다 5도 이상 낮으면 겉옷, 최저 5도 이하이면 따뜻한 외투, 최고 18도 미만이면 긴소매/가벼운 겉옷, 최고 28도 이상이면 통기성 좋은 옷·물, 일교차 10도 이상이면 겹쳐 입기를 제안합니다. 일반 생활 기준으로 개인 체감에 맞게 조절해야 합니다. 비교 자료가 없으면 기온 하락을 주장하지 않고 오래된 수치는 쓰지 않습니다. 기상 특보·실시간 강수 관측을 대체하지 않습니다.
- 자동 모드의 정보성 조언은 기본 날씨 답변 뒤에 음성과 채팅으로 안내하며 별도 앱을 열지 않습니다. 카드에는 이유·조회 시각을 표시합니다. 같은 제안은 24시간 반복을 억제하고 유효기간을 확인합니다. 최근 50개 제안의 표시·실행 요청·차단·사용자 유용성 평가를 내용 없이 기록합니다. 실행 요청 횟수는 실제 완료나 모델 학습 성공 횟수가 아닙니다.
- `내일 외출 준비 도와줘`는 등록된 다음 일정·야외 여부·해당 시각 날씨를 최대 3단계/25초 범위에서 확인하고 일정 15분 전 준비 알림 하나를 제안합니다. 자동 모드이면 낮은 위험 알림은 설정에 따라 실행할 수 있습니다. 이동 시간은 조회하지 않았다고 명시하고 출발 시간을 추측하지 않습니다. 등록 장소가 확인되지 않으면 현재 위치의 날씨로 몰래 바꾸지 않습니다. 취소·주제 변경·실패·설정 변경 시 중단합니다.
- 모델 가중치 학습이나 자유 자율 에이전트가 아니라 안전한 고정 흐름의 연결입니다. 자동 테스트는 가짜 날씨·알림 예약을 이용합니다. 실제 아이폰의 위치·날씨·알림 권한·음성 출력은 별도 확인이 필요합니다.

### 개인 비서 2~3단계 보완 · 대화·실행·음성

- 새 입력·중지·백그라운드 전환은 음성 안내 뒤의 외부 실행을 포함해 진행 중 처리 Task를 취소합니다. TTS 콜백과 음성 인식 콜백은 현재 상호작용/인식 세션에만 적용합니다. 완료 콜백이 누락되어도 중지 시 대기 continuation을 해제하고, 늦은 콜백으로 이전 지도를 열거나 새 대화를 종료하지 않습니다.
- 목적지 후보 선택은 숫자 접두사만으로 매칭하지 않습니다. `2호선 강남역`, 기존 후보의 `강남구`와 다른 `강남구청` 같은 새 목적지는 새 검색으로 넘깁니다. 선택 문장에 새 이동수단이 있으면 현재 요청을 우선합니다. 이동수단 확인 중 완전한 새 명령도 이전 목적지를 재사용하지 않습니다.
- 기억 저장 제안은 정확한 승인 문장만 받고 중앙 안전 정책을 거칩니다. 알람 선택 후 수정·삭제도 실행 전에 안전 잠금을 재평가합니다. 새 완전한 알람 명령은 이전 선택 작업보다 우선합니다.
- `ToolExecutionCoordinator`는 시작 전에 취소된 작업을 실행하지 않고 취소 후 늦은 성공을 완료로 표시하지 않습니다. 시간 초과는 실행 여부가 불확실하므로 `.once` 옵션이 있어도 자동 재시도하지 않습니다. 명시적인 재시도 가능 오류만 기존 정책에 따라 재시도합니다. 제한 시간은 협력적 취소를 전제로 하며 이미 다른 앱/시스템에 전달된 동작을 되돌린다는 보장은 아닙니다.
- 통화 등 오디오 인터럽트가 시작되면 진행 중 음성 상호작용과 대기 실행을 중단합니다. 인터럽트 종료 후 자동으로 마이크나 이전 작업을 재개하지 않습니다. 마이크 입력 포맷이 유효하지 않거나 엔진 시작이 실패하면 세션을 정리하고 오류를 안내합니다.
- **설정 → 대화 AI → 음성 안정성 진단**에서 TTS 요청·시작·완료·재시도·시작/완료 시간 초과, 최근 요청→시작 지연, 인터럽트·경로 변경·인식 오류를 확인합니다. 숫자만 앱 메모리에 보관하며 재시작 시 초기화되고 외부 전송하지 않습니다. 콜백은 실제 청취나 묵음 여부의 증거가 아닙니다.
- 자동 테스트는 가짜 음성·지도 서비스를 통해 취소 후 늦은 콜백, 새 목적지/이동수단, 안전 잠금, 권한 실패와 오디오 인터럽트를 재현합니다. 실제 iPhone에서 스피커/이어폰/Bluetooth, 음악 재생 중 호출, 통화, 잠금·앱 복귀를 별도로 확인해야 합니다. API 품질이나 물리적인 소리 출력을 이 테스트가 검증하지는 않습니다.

## Mac Codex 내장 보조 서비스 (1~3단계)

멀티 에이전트 → Codex 연결 설정의 **보조 서비스 시작·자동 연결**을 승인하면 앱에 포함된 XPC 서비스가 로컬 연결 프로그램을 시작합니다. 터미널을 계속 열거나 JSON 연결 파일을 선택할 필요가 없습니다. **보조 서비스 중지** 또는 연결 해제로 종료하며, 앱 종료 시에도 연결 소유권을 회수합니다. 로그인 시 자동 실행은 등록하지 않습니다. 기존 CLI·App Server 선택과 수동 JSON 연결은 유지됩니다.

개인 Mac에 Python 3과 Codex가 설치되어 있어야 하며 기존 Codex 로그인(별도 App Server 로그인 포함)을 사용합니다. 런타임 설치·로그인 자체를 자동 수행하지 않습니다. JARVIS 본체의 샌드박스는 유지하고, 내장 서비스만 기존 로그인과 실행 파일 접근을 위해 별도 프로세스로 실행됩니다. 양방향 XPC 코드 서명을 확인하고 인증 정보는 메모리와 전용 파이프로만 전달합니다. 시작 시 로그인 상태·모델 목록만 확인하며 질문을 자동 전송하거나 중단된 대화를 재실행하지 않습니다. 파일 수정·셸 도구 권한은 아직 제공하지 않습니다.

## Mac Codex 로그인·복구·안정성 (4~6단계)

연결 방식 **App Server**를 선택하면 **ChatGPT 로그인**, **로그인 취소**, **전용 계정 로그아웃**을 앱에서 사용할 수 있습니다. 로그인은 공식 브라우저 인증이며 비밀번호·토큰을 JARVIS에 입력하지 않습니다. 최대 3분 동안 완료를 확인합니다. 기존 CLI 로그인은 별도로 유지합니다.

서비스 시작 승인에는 선택적으로 **같은 빌드·같은 연결 방식에서 10분 동안 최대 2회 연결만 자동 복구**하는 범위를 포함합니다. 이 옵션은 끌 수 있고, 중지·잠금·연결 방식 변경·개발 공간 이탈로 승인이 해제됩니다. 질문은 재전송하지 않습니다. 앱 또는 Codex 실행 파일 업데이트를 감지하면 이전 세션을 종료하고 다시 연결·상태 확인을 안내합니다. 재시작 후에는 연결 방식·복구 옵션만 유지하며 로그인·대화 파일은 삭제하지 않고 실행 승인은 복원하지 않습니다.

**연결 진단 확인**에서 보조 프로그램 버전, Python 버전, 요청 수와 최근 응답 지연을 볼 수 있습니다. 계정·입력·토큰·경로는 진단에 포함하지 않습니다. 개인용 Mac의 내장 서비스와 기존 수동 연결을 모두 지원하며, 자동 다운로드·자동 OS 로그인 시작·파일/셸 도구는 이번 범위에 포함하지 않습니다.

검증 내역과 제한: [Codex 서비스 4~6단계 검증](Documentation/CodexServiceStages4-6-2026-11-04.md).

### Mac Codex 세션·도구·파일 확장

프로젝트 작업 5~6단계(2026.11.18.1)는 `+` 메뉴의 **작업 세션·이력 관리…**과 **작업 확장·스킬·검색 설정…**에서 관리합니다. 전용 App Server에 저장한 세션의 재개·최신 작업에서 분기·보관/복원·삭제·문맥 압축을 지원합니다. 마지막 답변이 로컬에 저장됐는지와 프로젝트·확장 설정이 일치하는지 확인하며, 불확실한 작업은 자동 재실행하지 않습니다. MCP 도구는 등록한 서버와 도구 이름만 선택할 수 있고, 실행과 결과 전송을 각각 승인합니다. 검토한 스킬 문서와 선택적인 Tavily 검색도 같은 승인 흐름을 사용합니다. 검색 키는 Mac Keychain에 보관합니다. 임의 스킬 스크립트·플러그인 훅·컴퓨터 제어, 공식 앱의 계정 전체 대화/설정 동기화는 포함하지 않습니다. 기존 보조 프로그램은 최신 빌드로 재시작해야 합니다.

일반 대화의 전용 Codex 세션 재개·분기, 중단된 코드 작업의 명시적 재검토, HTTP MCP/OAuth 및 연결 저장, 별도 프로필의 플러그인 관리, Git 파일별 diff·빌드 오류 위치 미리보기, 여러 이미지·텍스트/PDF 첨부와 TXT/Markdown/PDF 답변 저장을 추가했습니다. 코드 작업은 원본 확인과 실행별 안전 승인을 유지하며, 재시작으로 이전 승인을 복원하지 않습니다. 첨부 PDF는 텍스트 추출만 지원하고 자료가 잘리면 표시합니다. 공식 앱 계정 대화·설정 양방향 동기화나 모든 플러그인의 자동 실행을 뜻하지 않습니다. 제한·저장 위치·권한·검증 방법은 [로컬 연결 설명](Tools/CodexLocal/README.md)을 확인하세요.

### Codex 프로젝트 작업 모드 — 1~4단계

Mac 개발 공간에서 프로젝트를 연결하면 설치된 Codex의 버전·생성 스키마를 확인한 뒤, 실제 App Server의 도구 호출을 통해 파일 목록·읽기·승인 변경·승인 검증을 한 작업 안에서 이어갑니다. 실행은 `CapabilityRegistry.codexAgentTools → AssistantIntent.codexLocal → SafetyPolicyEngine → Swift 실행기`를 거칩니다. 기존 변경안 검토 방식은 `+` 메뉴의 모드 토글로 유지합니다.

승인은 요청·프로젝트·작업에 묶이며 만료·취소·연결 변경·긴급 잠금 시 폐기합니다. 채팅에서 진행 상태와 승인 요청을 표시하고, 실제 파일 저장·백업·검증 사실을 모델 답변과 구분합니다. 내장 셸/권한 도구를 제한 없이 활성화하지 않으며, 실험적 dynamic-tool API 지원 여부를 검사합니다. 자세한 범위·승인·검증 제한은 [로컬 연결 설명](Tools/CodexLocal/README.md)을 확인하세요.
