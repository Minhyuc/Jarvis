# A 묶음 재점검·보완 (2026-10-29)

## 수정한 문제

1. 누적 변경 1,001개를 하나의 파일로 쓰면 자체 읽기 한도와 충돌하던 문제:
   새 변경만 전송하고 1,000개·4 MiB 단위로 분할. 내보내기 전 기존 파일과 합친
   이력 5,000개·파일 2,000개·기기 32개·전체 16 MiB 상한을 검증.
2. 시간대 이름만 원본 시간대로 붙이고 시각은 현재 기기 시간대로 표시하던 문제:
   시작·종료 모두 항목 시간대로 변환. 종일은 날짜만 표시.
3. 공유 폴더 손상·연결 해제 시 정상 로컬 DB도 조회하지 못하던 문제:
   독립 읽기 전용 API와 개발 공간의 오프라인 조회 진입점을 추가.
4. DB·백업 경로 보호 및 늦은 실패 보완:
   공유 루트 내부 DB, 사용자 지정 경로·백업 심볼릭 링크 거절.
   로컬 상태 32 MiB·원본 백업 8 MiB 제한도 미리보기에서 검사.
5. 같은 변경 ID가 서로 다른 내용을 갖는 교환 파일을 조기에 거절.
   로컬 상태 로딩에서도 레코드·부모·헤드·충돌 참조 일관성을 검사.

## 호환성·안전 경계

기존 형식 1의 누적 대형 묶음(최대 5,000변경)은 기존 전체 용량/이력 상한 내에서
읽기 호환한다. 파일을 고치거나 지우지 않는다. 새 출력은 1,000개 이하이다.
기준 부모 파일이 도착하지 않으면 부분 병합하지 않고 보류한다.
공유 자료가 손상되어도 독립 조회는 마지막 정상 로컬 DB를 읽는다.
조회 시각은 원격 갱신·수신 확인 시각이 아니다.

승인·취소·긴급 잠금 정책, 일반 파일 도구의 보호 영역, 기존 iPhone 운영 JSON과
실제 알림 예약은 유지했다. 모델 호출·자동 동기화·백그라운드 예약을 추가하지 않았다.

## 검증 범위

격리된 임시 폴더·기기별 DB에서 회귀 테스트를 수행한다. 검증 사례:

- 1,001변경 분할, 재내보내기 중복 없음, 추가 변경만 전송, 두 DB 병합.
- 4 MiB 초과 자료의 바이트 기준 분할과 기존 누적 대형 파일 호환.
- 전체 용량·빈 기기 폴더 포함 기기 수·파일 수·합산 고유 이력 한도 초과 시 쓰기 전 거절.
- 공유 폴더 손상·이동 후 재시작한 엔진에서 로컬 조회, 조회 시 DB 미생성/미변경.
- 오프라인 조회의 잠금·취소, 타입이 있는 삭제표식·충돌 모델.
- 다른 시간대와 뉴욕 서머타임 종료 구간의 시작·종료, 종일 날짜.
- 공유 루트 내부 DB·심볼릭 링크·원본 백업 한도 및 기존 승인/취소/보호 회귀.

로컬 테스트와 iOS Simulator/Mac 빌드 성공은 실제 iCloud 전달의 증거가 아니다.
실제 iPhone·Mac의 권한 회수, 다운로드 대기, 동시 오프라인 변경은 두 기기로 별도 확인해야 한다.
B의 월간·일간 관리 화면, 충돌 해결·백업 복구 UI는 아직 구현하지 않았다.
C의 운영 목록 및 실제 예약 반영과 D의 자동 동기화·보관 정책도 남아 있다.
