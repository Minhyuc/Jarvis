# 수동 데이터 동기화 · A 묶음

## 범위

서버·CloudKit·REA·OpenAI 호출 없이 시스템 폴더 선택창의 권한으로 동작합니다.
각 기기는 Application Support/JARVIS/SharedSync/<저장소 UUID>.sqlite를 사용합니다.
기존 iPhone 운영 JSON은 건드리지 않고, 승인된 수동 수집만 별도 SQLite로 가져옵니다.
가져온 자료는 예약 실행 명령이 아닙니다. 실제 예약과 운영 목록 반영은 C 단계에서 연결합니다.
Mac의 현재 화면은 수동 동기화 목록이며 월간·일간 관리 화면은 B 단계입니다.

## 순서

1. iPhone·Mac에서 같은 iCloud Drive 폴더를 선택하고 읽기/승인 후 쓰기를 허용합니다.
2. **전체 저장하기:** iPhone 현재 목록 수집·공유 기록 생성을 한 번에 미리보고 승인합니다.
   최초 초기화도 같은 승인에 포함합니다. Mac은 자체 동기화 DB만 기준으로 내보냅니다.
3. **전체 불러오기:** 공유 기록을 검증하고 최초 로컬 DB 준비·병합을 한 번에 승인합니다.
   공유 폴더에 저장 자료가 없다면 먼저 iPhone에서 전체 저장하기를 실행합니다.
4. **DB 조회:** 알람·일정·삭제표식·충돌을 확인합니다. 공유 폴더 연결 없이도 가능합니다.
5. iPhone에서 수정한 뒤 전체 저장하기 → iCloud 전송 확인 → 다른 기기의 전체 불러오기 순서입니다.

전체는 현재 목록 전체를 비교한다는 뜻이며, 이미 전송한 이력까지 중복 저장하거나 충돌을
강제 덮어쓰는 기능이 아닙니다. 모든 단계는 승인 전 메모리에서 준비하고 크기·경로·기준 버전을
검증합니다. 승인 후 일부 파일 기록과 DB 저장 사이에서 중단되면 미확인 상태를 안내합니다.
실제 iPhone 운영 목록·OS 예약을 복원하는 기능은 아직 C 단계 범위입니다.
일반 TXT 파일·폴더는 SQLite에 넣지 않고 공유 폴더의 실제 파일로 관리합니다.

이미 처리한 변경은 재적용하지 않습니다. 내보내기 묶음은 내용 해시 파일명이며 기존 동일
내용은 재기록하지 않습니다. 이미 공유한 변경 ID는 제외하고 새 변경만 최대 1,000개·4 MiB로
분할합니다. 파일 수·기기 수·전체 바이트 한도도 승인 전 검증합니다. 중단 후 완전히 기록된
묶음은 다시 보내지 않습니다. 각 묶음은 완전한 하나의 JSON 파일이므로 부분 도착·손상은
승인하지 않습니다. 여러 묶음의 기준 이력이 누락되면 전체 가져오기를 보류합니다.
기존 누적 내보내기가 만든 형식 1의 1,001~5,000변경 파일은 파일당 4 MiB·전체 이력/용량
한도 안에서만 읽기 호환합니다. 새 파일은 항상 1,000개 이하입니다. 기존 파일을 재작성하지 않습니다.

## 오프라인 조회와 B 단계 연결

개발 공간 → iCloud 공유 프로젝트의 **이 기기의 동기화 DB 보기 (오프라인)**는 공유 폴더 선택/접근 허용 없이
이미 저장된 저장소 ID를 선택해 마지막 로컬 사본을 조회합니다. 공유 파일의 손상·권한 회수·폴더
이동과 독립적입니다. 조회 시각은 원격 갱신·수신 확인 시각이 아니며 데이터가 오래되었을 수 있습니다.
안전 잠금·중지·화면 이탈 시 조회를 중단하고 표시 내용을 지웁니다. DB 조회는 DB가 없으면 생성하지 않습니다.

`localStorageIDs`와 `localSnapshot`은 읽기 전용 API이며 `SharedSyncSnapshot`의 타입이 있는
heads(삭제표식 포함), conflicts, storageID, generation을 제공합니다. B 단계는 표시 문자열을
파싱하지 않고 이 모델을 사용합니다. 손상된 로컬 DB는 복구를 시도하거나 빈 목록으로 대체하지
않고 오류로 표시합니다. 공유 파일을 검증하는 기존 `status` API와 구분합니다.

## 형식

공유 루트 아래 알람/항목, 캘린더/항목, 메모, 시스템/{동기화/{변경기록,수신확인},
삭제표식,충돌,복구}, JARVIS 복구함을 생성합니다. 저장소정보.json은 형식 1과 저장소 UUID입니다.
변경기록/<기기 UUID>/<SHA256>.json이 실제 교환 자료입니다. UUID는 하드웨어/Apple ID가 아닌
로컬 임의 ID입니다. 묶음에는 형식·저장소·기기·변경 배열이 있으며 각 변경은 UUID, 항목 키,
직전 변경 UUID, 시각, 항목 또는 null 삭제표식입니다. 시각 비교로 승자를 고르지 않습니다.
JSON Date는 Foundation JSONEncoder 기본 형식(2001년 기준 초)입니다. OS ID·승인·키 필드는 없습니다.
형식 변경 시 버전을 올리고 명시적 마이그레이션을 추가해야 합니다.

항목 스냅샷·수신확인·복구 폴더의 파일 생성은 향후 단계용입니다. A에서 별도 JSON 파일이
없는 삭제표식/충돌도 변경기록과 로컬 SQLite 안에 유지합니다. 정리/압축은 자동 수행하지 않습니다.
백업은 공유 폴더가 아니라 각 기기의 SharedSync/백업에 UUID별 파일로 남깁니다. 이전 DB 상태와
iPhone 원본 백업을 보존합니다. 백업 복구 UI/보관 정리는 B/D 범위이며 자동 삭제하지 않습니다.

## 시간·지원 범위

기존 운영 모델이 가진 필드만 이전합니다. 알람의 날짜·시스템음/TTS·활성화·라벨/안내 내용,
일정의 시작/종료·종일·장소·메모·URL·야외·기존 반복·알림 분을 지원합니다. 시간대가 없던
원본은 수집 시 현재 기기의 시간대를 기록합니다. 원래 입력한 시간대를 복원했다고 주장하지 않습니다.
시작/종료 표시는 기기 시간대가 아닌 항목 시간대로 변환합니다. 종일 일정은 시각 없이 날짜를
표시하고 종료 날짜는 저장된 종료 경계 그대로 표시합니다. 현재 운영 모델의 시간대 정보 부재로,
여행 후 재수집 시 시간대 메타데이터가 변경될 수 있습니다.
반복 알람·일정의 특정 회차 예외는 기존 운영 모델에 없어 지원하지 않습니다. 해당 알람을
외부 형식으로 임의 추가하면 버전 검증에서 거절합니다. 기록은 C 단계까지 실제 예약에 사용하지 않습니다.

한도: 현재 항목 1,000개, 이력 5,000변경, 기기 폴더 32개, 교환 파일 2,000개,
파일당 4 MiB, 전체 교환 16 MiB, 로컬 DB 상태 32 MiB. 삭제표식/충돌도 이력 한도에 포함됩니다.
한도를 넘으면 압축/임의 삭제하지 않고 중단합니다. 이는 초기 수동 동기화 한도이며 장기 운영에는
D 단계의 확인 기반 보관·압축 정책이 필요합니다.

## 안전

각 미리보기는 한 엔진의 최신 단일 계획이며 2분 뒤 만료합니다. 적용 직전 공유 자료 해시,
로컬 DB 세대, 잠금·취소를 재확인합니다. 승인 없는 모든 쓰기는 차단합니다. 일반 파일 도구는
알람/캘린더/시스템과 그 내용을 포함하는 상위 폴더를 생성·수정·이동·삭제할 수 없습니다.
Finder 외부 수정까지 막는 OS 권한 장치는 아니므로 매번 형식·경로·링크·파일 버전도 검사합니다.
로컬 DB 디렉터리는 공유 루트 내부에 둘 수 없고, 로컬 경로/백업의 사용자 지정 심볼릭 링크를
거절합니다. 원본 백업·DB 크기 한도는 미리보기에서도 확인하여 뒤늦은 실패를 줄입니다.
체크섬은 손상 탐지일 뿐 작성자 인증이 아닙니다. 공유 폴더 접근자를 신뢰할 수 있는 범위로 제한하세요.
내용은 모델·메모리·학습 자료로 전송하지 않습니다. 데이터가 명령처럼 보여도 실행하지 않습니다.
안전 정책·권한·감사·예약 ID는 원격으로 적용하지 않습니다.

NSFileCoordinator는 같은 기기의 파일 접근 조정이며 오프라인 기기 전체를 잠그는 장치가 아닙니다.
승인·백업·공유 파일·DB를 하나의 분산 트랜잭션으로 묶었다고 주장하지 않습니다. 중단 시 일부
디렉터리/완전한 교환 묶음이 이미 기록될 수 있습니다. 빈 초기화 구조는 재검토하여 재개할 수 있고,
묶음은 불변·중복 방지하므로 다시 검토해 처리합니다. 모르는 기존 구조는 덮어쓰지 않습니다.

## 실제 두 기기 확인 체크리스트

- 동일 Apple 계정의 iCloud Drive에서 같은 폴더·저장소 ID를 선택했는지 확인.
- 테스트 알람·일정 1개만 수집·내보내기, Mac 가져오기로 제목/날짜/시간대/반복/TTS/메모 확인.
- 가져온 자료가 기존 운영 캘린더·알람을 바꾸거나 예약을 실행하지 않는지 확인.
- 재가져오기·재내보내기 시 중복이 없는지 확인.
- iPhone에서 테스트 항목 수정·삭제 후 재수집·교환하여 삭제표식이 유지되는지 확인.
- 미리보기 후 항목 수정 시 승인이 거절되는지 확인.
- 잠금·중지·화면 이탈·앱 종료·권한 회수 시 기존 데이터/백업이 유지되는지 확인.
- 오프라인/다운로드 대기/손상 파일이 삭제로 처리되지 않는지 확인.

자동 테스트는 격리된 임시 폴더와 기기별 DB 두 개를 사용합니다. 로컬 테스트 성공은 실제
iCloud 전달, 잠긴 iPhone의 예약 반영, TTS 출력 성공의 증거가 아닙니다.
