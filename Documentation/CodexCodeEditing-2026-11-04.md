# JARVIS 내부 Codex 코드 수정

## 소스 확인 오류 보완

한 파일이 크기·범위·형식·비밀 키 검사에 실패하면 전체 요청을 버리던 경로를 수정했다. `previewReads`는 현재 목록 안의 파일만 로컬에서 읽고, 정상 파일과 실제 줄 범위·제외 이유를 돌려준다. 파일당 32KiB·전체 96KiB 한도는 유지하며 초과 범위는 완전한 줄 단위로 줄인다. 한 줄 자체가 너무 길거나 원본이 1MiB를 초과하면 제외한다. 키 감지 파일은 계속 전송 차단한다. 부분 결과도 새 UUID의 허가 카드에서 사용자 승인을 받아야 전송된다. 잠금·취소는 부분 결과를 반환하지 않는다.

읽기 응답 스키마도 최대 8개 파일·1~600줄·시작 줄 범위를 명시한다. [공식 Structured Outputs 스키마 제약](https://developers.openai.com/api/docs/guides/structured-outputs#supported-schemas)을 따르며 Swift에서도 다시 검증한다. helper build는 2026.11.04.5다. 별도의 Codex native 파일·셸 도구 활성화는 이 수정에 포함하지 않는다.

## 사용자 흐름

최신 Mac 앱 → 멀티 에이전트 → App Server 연결·로그인 → 입력창 위 프로젝트 폴더 연결. 기본 채팅에서 수정 요청을 보낸다. 먼저 요청·상대 파일 목록·같은 대화의 최근 최대 3회 문맥만 전송한다. 모델이 reads(path/startLine/lineCount)를 반환하면 대화 안에서 해당 범위의 소스 읽기·외부 전송을 승인받는다. 거절 시 취소한다. 추가 범위는 다시 승인받으며 한 작업 최대 5회 모델 요청·5분으로 제한한다. 모델·추론은 입력창의 선택을 사용한다. 변경 전후·적용·복구도 대화에 표시한다.

소스 첨부·변경 계획은 메모리에만 두며 대화 전환·새 명령·모델/연결 변경·잠금에서 폐기한다. 프로젝트 변경·화면 이탈은 폴더 접근까지 해제한다. 자연어 기록은 coding 표식과 함께 로컬 저장하고 일반 채팅 프롬프트에는 포함하지 않는다. 같은 코드 대화의 성공 응답만 AssistantContextManager를 거쳐 제한적으로 사용하며, 수정 전에는 새 코드 범위를 요청한다. 보호 코드·셸 권한은 기존대로 차단한다. protocolVersion 3 / codeVersion 2, helper build 2026.11.04.4를 사용한다. 이전 보조 프로그램은 재시작해야 한다.

응답은 summary와 edits(path/old/new) JSON이며 원본 변경 권한이 아니다. 사용자에게 기존 부분과 제안 부분을 전부 표시하고 파일별 승인 후 적용한다. 새 파일은 기존 디렉터리 안에 생성한다. 폴더 생성·파일 삭제·자동 코드 실행은 이 흐름에 포함하지 않는다. 원래 없던 파일의 백업 복구는 생성한 파일을 제거한다는 내용을 보여주고 별도 승인한다.

## 권한 경계

codeConnect/codeDraft/codeApply/codeRestore는 고위험 개별 승인이다. codeRead는 잠금에 민감한 조회다. 이들은 CapabilityRegistry·일반 명령 분류·AIClient에 등록하지 않는다. 셸·MCP·기본 도구 비활성화와 읽기 전용 native sandbox는 유지한다. helper는 원본 경로나 root handle을 받지 않고 선택한 스냅샷만 받는다. source 전송 전 AssistantContextManager의 격리된 빈 문맥을 확인한다. 사용자 파일 내용은 개발자 지시로 사용하지 않는다.

App Server는 요청당 독립 ephemeral thread와 outputSchema를 사용하고 종료 후 해당 thread alias를 폐기한다. 코드 내용이나 실패한 수정안을 일반 채팅의 문맥으로 재사용하지 않는다. codeVersion 1을 추가해 이전 text helper를 변경안 기능으로 오인하지 않도록 한다. 자동 복구는 기존 전송 계층 범위만 유지하며 코드 요청을 재전송하거나 변경안을 자동 적용하지 않는다.

## 로컬 파일 실행기

CodexCodeFiles는 상대 경로와 허용 확장자, root inode, 심볼릭 링크·하드 링크, UTF-8·NUL·크기, 눈에 띄는 개인 키 패턴을 검사한다. 민감한 파일 이름·숨김 경로·공유 알람/일정/시스템 영역과 안전·인증·실행기·Codex·빌드 설정·AGENTS 코드를 수정 대상에서 제외한다. 비밀정보 검사는 보조 방어이며 모든 비밀을 탐지한다고 보장하지 않으므로 전송할 코드를 사용자가 확인한다.

모델이 제시한 old는 첨부 범위에 있고 로컬 전체 원본에서 정확히 한 번 일치해야 한다. 겹치는 변경을 거부하고, 범위 밖의 파일 변경·기존 파일의 생성 덮어쓰기를 거부한다. 원본 전체는 전송하지 않고 버전 확인과 변경 적용에만 사용한다. 생성은 사용자 검토에 표시된 허용 경로만 가능하다. 심볼릭 링크를 따라가지 않는 디렉터리 FD와 openat/renameat 기반 파일 작업을 사용한다.

파일마다 별도 승인하며 NSFileCoordinator, 원본 일치 재검사, 임시 파일·원자적 교체를 사용한다. 파일 제공자의 조정 대기는 제한하고 잠금·취소를 commit 전에 재검사한다. 일반 사용자의 협조되지 않은 외부 쓰기와 전원 장애 전체를 파일 시스템 트랜잭션으로 보장하는 것은 아니며, 쓰기 후 확인 실패는 unverifiable로 표시한다. 안전 잠금 중 승인으로 우회할 수 없다. Git reset/clean을 사용하지 않아 기존 dirty working tree를 보존한다.

백업은 앱의 Application Support/JARVISCodexCodeBackups/프로젝트ID 아래 개인 파일로 저장한다. 원본이 아닌 앱 전용 저장소이며 iCloud로 내보내지 않는다. 소스/변경/백업/승인은 안전 감사 로그에 넣지 않는다. 백업은 최대 100개까지 보존하고 임의 삭제하지 않는다. 복구는 현재 파일이 적용 직후 내용과 같을 때만 허용한다. 디스크 원본·백업은 자동으로 실행하지 않는다.

## 제한과 검증

확인 결과: Swift 테스트 305개, Python 테스트 53개 통과. 실제 App Server에 가상 파일 목록만 제공해 읽기 요청을 받은 뒤, 가상 코드 한 줄을 제공해 변경안까지 받는 2회 모델 호출을 앞선 단계에서 검증했다. 이번 수정은 긴 범위 축소·일부 파일 실패·비밀 키 차단·총량 제한·잠금·취소를 임시 파일로 추가 검증했다. Mac UI 검증기는 합성 모델 응답을 임시 소스 적용·복구 검사로 연결한다. 실제 프로젝트 소스는 모델 검증에 전송하지 않았다.

파일 목록 최대 1000개·32KiB, 첨부 최대 8개·96KiB, 범위당 최대 600줄·32KiB, 원본 파일당 1MiB, 모델 제안 최대 16개 교체·64KiB, 검토 계획 10분·현재 root session·단회 적용으로 제한한다. 대화 전환은 소스 문맥·승인을 폐기하고 프로젝트 변경·화면 이탈은 폴더 권한까지 해제한다. 백업은 같은 root identity에서 다시 확인할 수 있다.

Swift 테스트는 실제 임시 소스 파일의 적용·영구 백업·복구·생성·승인·잠금·commit 직전 잠금·취소·외부 수정 충돌·보호 경로·traversal·symlink·hardlink·코드 범위·비밀정보·중첩 변경·만료·재연결·프로토콜을 검증한다. Python 테스트는 전용 HTTP 규격·출력 schema·도구 차단·일반 대화 문맥 격리를 검증한다.

smoke_code.py는 실제 모델에 합성 코드 한 줄만 전송해 JSON 변경안을 확인한다. check_mac_ui.py는 이 합성 응답이 있으면 Swift 검증 → 임시 소스 적용 → 백업 복구까지 이어서 확인한다. 실제 사용자 프로젝트는 검증 요청에 전송하거나 수정하지 않는다. 통합 코드는 swift test, Mac 빌드, unsigned iOS Simulator 빌드로 확인한다. 모델이 만든 임의의 JARVIS 수정안 자체가 빌드를 통과했다는 의미는 아니다.
