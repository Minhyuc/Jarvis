# iCloud 공유 프로젝트와 JARVIS Mac

알람·캘린더의 별도 수동 교환은 [데이터 동기화 안내](SharedDataSync.md)를 참고하세요.
`알람`, `캘린더`, `시스템` 영역은 일반 파일 도구로 변경할 수 없습니다.

## 음성·채팅 명령과 폴더/메모 정리

iPhone에서는 JARVIS 음성·채팅, Mac에서는 개발 공간의 **명령 확인**으로 요청합니다.
먼저 개발 공간에서 공유 폴더를 선택해야 하며, 앱 재실행 시 다시 선택합니다.
경로는 항상 선택한 공유 폴더의 최상위 기준입니다. 현재 화면의 폴더를 임의로 재사용하지 않습니다.

예시:

```text
공유 폴더의 메모 폴더 만들어줘
공유 폴더의 메모 폴더에 장보기 메모 만들어줘 내용은 우유와 달걀
공유 폴더의 "메모/장보기.txt" 메모 수정해줘 내용: 우유 두 개
공유 폴더의 "기록" 폴더 만들어줘
공유 폴더의 "메모/장보기.txt" 파일을 "기록/장보기.txt"로 옮겨줘
공유 폴더의 "기록/장보기.txt" 파일 삭제해줘
```

공백이 포함된 이름이나 여러 단계의 경로는 따옴표와 `/`로 정확히 지정합니다.
메모 확장자가 없으면 `.txt`를 붙이며 명령 메모는 내용 4 KiB까지 지원합니다.
`내용:`/`내용은` 뒤의 문장은 메모 데이터로만 취급하고 그 안의 명령을 실행하지 않습니다.
지원하지 않는 표현은 재질문하며 범용 모델로 파일 변경을 추측하지 않습니다.

JARVIS는 실제 허용 폴더 이름·상대 경로·메모 내용·이동 목적지를 읽고 확인을 요청합니다.
직전 확인 질문에 승인해야 하며, 거절·새 명령·만료·폴더 재선택·취소 시 이전 승인을
재사용하지 않습니다. 파일 작업이 실제로 확인된 뒤에만 완료를 안내합니다.
다른 기기로의 iCloud 동기화까지 완료됐다고 주장하지 않습니다.

버튼 사용: **새 폴더/새 메모**는 화면에 표시된 현재 폴더 안에 만듭니다.
항목 오른쪽 **관리**에서 전체 상대 목적지를 입력해 이동/이름 변경하거나 삭제합니다.
기존 목적지는 덮어쓰지 않으며 없는 부모 폴더를 자동 생성하거나 비슷한 다른 이름을 찾지 않습니다.

삭제는 영구 제거가 아니라 같은 프로젝트 안의 **JARVIS 복구함/고유ID-이름**으로 이동합니다.
폴더도 내용과 함께 보존합니다. **이번 연결에서 삭제한 항목 복구**는 원래 위치로 되돌리되
그 위치에 항목이 생겼으면 덮어쓰지 않습니다. 앱 재실행 뒤에도 실제 복구함은 남습니다.
그 경우 복구함에서 해당 항목의 **관리**를 눌러 원래 상대 경로를 지정해 이동하거나
Finder/파일 앱에서 직접 복구하세요. 복구함을 자동 비우는 기능은 없습니다.

폴더 이동/삭제는 최대 500항목, 깊이 12, 내용 합계 8 MiB까지만 사전 검사합니다.
숨김 파일(.git/.env 등), 심볼릭/하드 링크, 빌드 폴더, 바이너리·민감 이름·미지원 항목,
충돌 버전이 있으면 전체 작업을 차단합니다. 소규모 메모/코드 정리용이며 임의 프로젝트 전체
정리 도구가 아닙니다. 승인 후 원본 내용이 바뀌면 이동·삭제를 거절합니다.

## 처음 실행

1. Finder의 **iCloud Drive**에 전용 `JARVIS` 프로젝트 폴더를 준비합니다.
   이미 만든 폴더를 사용해도 됩니다. API 키·인증서·개인 비밀정보는 넣지 마세요.
2. Mac과 iPhone에서 같은 Apple 계정의 iCloud Drive를 사용하거나, 양쪽 계정에
   쓰기 권한이 있는 공유 폴더인지 확인합니다. 앱이 공유 초대·Apple 계정 설정을 대신하지 않습니다.
3. iPhone: 기존 `Jarvis.xcodeproj` → `Jarvis`로 빌드한 앱에서 왼쪽 위 구름 아이콘
   **개발 공간 → 프로젝트 폴더 선택 → iCloud Drive의 해당 폴더**를 선택합니다.
4. Mac: `JarvisMac/JarvisMac.xcodeproj`를 Xcode에서 엽니다. 스킴 **JarvisMac**, 실행
   대상 **My Mac**을 선택하고 실행합니다. 앱 이름은 **JARVIS**(`JARVIS.app`)이며,
   개발용 프로젝트·스킴 이름만 `JarvisMac`으로 유지합니다. macOS 14 이상이 필요합니다.
   서명이 필요하면 Signing & Capabilities에서 본인 Team을 선택합니다.
5. Mac 앱에서도 같은 iCloud 폴더를 선택하고 **읽기·승인 후 쓰기 허용**을 누릅니다.
   Mac App Sandbox와 User Selected File Read/Write를 유지하세요. 전체 디스크 접근은 필요 없습니다.

별도의 iCloud 컨테이너 ID나 앱 전용 CloudKit 데이터베이스를 만들지 않습니다.
시스템 문서 선택창이 사용자가 선택한 폴더의 접근 권한을 제공하고, iCloud Drive가
파일 동기화를 담당합니다. IP·Mac 서비스·Python은 이 기능에 필요 없습니다.
폴더 선택창에는 로컬/다른 제공자도 나타날 수 있습니다. iCloud Drive를 직접 선택해야 공유됩니다.

## 파일 작업

- 연결 후 **목록 새로고침**을 눌러 폴더를 탐색합니다. 하위 폴더는 클릭하고
  **상위 폴더**로 돌아옵니다. 숨김 파일/빌드 결과 등은 제외됩니다.
- 파일을 누르면 코드 편집기가 열립니다. 수정 후 **변경 비교·저장**에서 변경 전과
  저장할 내용을 확인하고 해당 파일의 저장을 승인합니다.
- **새 파일**에 `main.swift`, `note.md` 같은 이름을 입력하면 빈 파일을 생성합니다.
  생성에도 확인이 필요하며 이미 존재하는 이름은 덮어쓰지 않습니다.
- 다른 기기에서 수정했으면 저장하지 않고 경고합니다. 편집기의 초안을 복사한 뒤
  **변경 취소 → 파일 다시 열기**로 새 원본과 비교합니다. 자동 덮어쓰기/자동 재시도는 없습니다.
- 편집 중에는 다른 파일 열기와 폴더 전환을 막습니다. 저장 또는 변경 취소 후 이동하세요.
  앱 종료/화면 이탈로 초안이 사라질 수 있습니다. 자동 저장·초안 디스크 복구는 제공하지 않습니다.
- 중지는 아직 커밋되지 않은 작업을 막고 늦은 화면 결과를 무시하지만 이미 저장된
  파일을 되돌리는 기능은 아닙니다. 저장 여부가 불명확하면 다시 열어 확인합니다.
- 연결 해제는 권한 URL과 화면 내용을 해제할 뿐 실제 파일을 삭제하지 않습니다.
  권한/경로를 영구 저장하지 않으므로 앱 재실행 시 폴더를 다시 선택합니다.
- 다른 기기에서 작업한 뒤에는 **목록 새로고침 → 파일 다시 열기**로 최신 내용을 확인합니다.
  자동 실시간 공동 편집/문자 단위 병합/Apple 계정 또는 AI 기억 동기화는 아직 없습니다.

## 실제 두 기기 검증

실제 iCloud 공유는 로그인된 두 기기에서 별도로 확인해야 합니다. 코드 테스트와
로컬 시뮬레이터 빌드는 클라우드 동기화 성공의 증거가 아닙니다.

1. Mac 앱에서 `connection-test.txt`를 생성하고 테스트 문장 하나를 저장합니다.
2. Finder에서 iCloud 업로드 상태를 확인합니다.
3. iPhone 앱에서 같은 폴더를 새로고침하고 해당 파일을 열어 같은 내용을 확인합니다.
4. iPhone에서 문장을 변경·승인 저장한 뒤 Mac에서 다시 열어 반영을 확인합니다.
5. 한 기기에서 원본을 연 상태에서 다른 기기가 변경하게 한 후, 예전 원본의 저장이
   거절되는지 확인합니다. 동기화 전 오프라인 충돌은 iCloud가 늦게 알릴 수 있으므로
   여러 기기에서 같은 파일을 동시에 수정하지 않는 것이 현재 안전한 사용 방식입니다.
6. 안전 잠금 시 목록/열기/저장이 차단되고 접근 해제/중지는 가능한지 확인합니다.
7. 폴더 선택 취소·권한 거부·네트워크 끊김·iCloud 미다운로드 파일도 확인합니다.

## 보안과 한계

파일/폴더 허용과 개별 저장 승인은 별개입니다. `SharedProjectFiles`는 UI 전용
결정론적 실행기이며 모델용 CapabilityRegistry에는 노출하지 않습니다.
외부 AI·REA 전송이나 코드 실행 기능은 없고 Mac 앱의 네트워크 권한도 추가하지 않았습니다.
민감 이름 제외는 비밀정보 완전 검출이 아닙니다. 선택한 텍스트가 화면에 표시되며
승인 저장한 내용은 iCloud를 통해 다른 기기로 전달될 수 있습니다.
디스크 저장 검증만 성공으로 표시하며 원격 동기화나 컴파일 성공으로 말하지 않습니다.
공유 폴더 내용이 안전 정책·승인·API 키·기기 잠금을 변경할 수 없습니다.
기기별 안전 잠금은 공유되지 않습니다.

사용 API 근거: [Apple의 폴더 접근 안내](https://developer.apple.com/documentation/uikit/providing-access-to-directories),
[SwiftUI 파일 선택창](https://developer.apple.com/documentation/swiftui/view/fileimporter(ispresented:allowedcontenttypes:oncompletion:)).
