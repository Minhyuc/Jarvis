# 호출 음성 및 비동기 안정성 점검

## 범위와 증거의 한계

프로젝트의 호출 진입점, TTS/미리 듣기/알림 파일 렌더러, 인식 세션, 대화 상태,
단축어·도구 실행, 공유 폴더, 학습 작업의 비동기·취소 패턴을 정적으로 점검했습니다.
전체 앱의 컴파일 및 기존 코어 회귀, 음성/대화 E2E를 병행했습니다. 모든 코드의
모든 실행 경로를 실기기에서 재현한 전수 검증 또는 보안 인증이라는 뜻은 아닙니다.
재시도 때 음성을 바꾸는 기존 코드 경로는 확인했지만 사용자가 들었던 특정 소리가
그 경로인지, Siri의 자체 응답인지 실제 장치 녹음 없이 단정할 수는 없습니다.

## 확인하고 수정한 문제

1. **시작 실패 시 목소리 변경**: 재시도가 `honoringSavedPreference: false`로 설정을
   무시했습니다. 요청 시 음성을 한 번 결정해 재사용하고, 품질 점수가 같은 자동 후보는
   식별자로 안정적으로 정렬합니다. 시작 실패만 한 번 재시도합니다.
2. **저장 설정 자동 소실**: 설정 화면을 열 때 음성 목록에 없으면 선택을 지웠습니다.
   값을 보존하고 사용 불가 항목으로 표시합니다. 실제 대체 사용은 내용 없는 횟수로 진단합니다.
3. **미리 듣기 별도 구현/늦은 재생**: 별도 synthesizer/지연 Task를 공통 TTS로 통합했습니다.
   화면 이탈·비활성화·음성 변경·새 명령 시 취소하고, 미리 듣기 시작 전에 VM의 기존
   마이크·재생·실행 대기자를 정리합니다. 새 명령도 미리 듣기를 중지합니다.
4. **이미 시작한 음성 재방송**: 취소 콜백이 항상 처음부터 재시도했습니다. 이미 시작한
   발화는 재생하지 않습니다. Stop·설정 변경·새 입력 이후의 콜백은 무시합니다.
5. **동일 턴의 중복 완료**: VM의 일반 음성 완료도 상호작용 ID 외 재생 ID로 한 번만
   소비합니다. 중복 콜백이 마이크 재시작/오디오 해제를 반복하지 못합니다.
6. **호출 플래그 수명**: 비활성화 중 대기 요청을 소비하지 않으며 명령 처리 시 함께 남은
   호출 플래그를 지웁니다. 계정 로그인 등 처리와 음성 호출은 기존 분기를 유지합니다.
7. **늦은 인터럽트 이벤트**: 알림의 처리 Task가 새 턴을 취소할 수 있었습니다. main queue의
   관찰자에서 해당 시점의 턴을 동기적으로 중지해 뒤늦은 취소 Task를 만들지 않습니다.
8. **노래 찾기 대기 후 정책 누락**: 안내 후 1.5초 대기 뒤 및 외부 앱 실행기 진입 시
   취소·안전 잠금을 재확인합니다. 실행 권한을 늘리거나 잠금 예외를 추가하지 않습니다.

## 자동 검증

- Core 전체: 기존 명령·안전 정책·기억·동기화 회귀 262개.
- 최종 iOS Simulator 빌드·실행: SpeechVoiceLifecycleTests, AssistantTurnLifecycleTests,
  AssistantViewModelE2ETests, ProjectCommandE2ETests 합계 31개 통과, 실패/건너뜀 0개.
- Fake synthesizer: 실제 오디오를 재생하지 않고 시작 취소/타임아웃, 음성 고정,
  재시도 상한, 중간 취소, 늦은 완료, 미리 듣기 종료/새 명령을 검증합니다.
- 실제 AssistantViewModel: 가짜 도구/음성으로 음성 설정·미리 듣기·통화 인터럽트 후
  대기 실행이 취소되는지, 이전 콜백이 새 턴에 영향을 주지 않는지 확인합니다.
- 단축어 플래그는 별도 UserDefaults suite에서 검증합니다. 새로 추가한 테스트가
  사용자 Google 계정에 로그인하거나 실제 URL을 실행·녹음하지 않습니다.
- 시작/완료 콜백 통과는 사람이 실제 소리를 들었다는 증거가 아닙니다.

## 실제 iPhone 확인 절차

1. 업데이트 앱을 설치하고 설정에서 설치된 한국어 음성을 직접 선택합니다.
2. 미리 듣기 후 바로 설정을 닫아 늦은 미리 듣기가 나오지 않는지 확인합니다.
3. 앱의 한 번만 대화하기와 Siri/음성 단축어 호출을 각각 반복해 구분합니다.
4. 호출/답변 중 정지 → 새 명령을 반복하고 이전 답변·마이크가 살아나지 않는지 확인합니다.
5. 설정에서 목소리를 바꾸고 호출·일반 응답을 비교합니다. 이미 예약된 TTS 파일은
   이전 목소리일 수 있으며 이번 변경은 예약 내용을 자동 갱신하지 않습니다.
6. 스피커·이어폰·Bluetooth 및 잠금 해제 직후를 구분해서 확인합니다.
7. 문제가 남으면 **설정 → 음성 안정성 진단**의 재시도/시간 초과/저장 음성 사용 불가
   횟수와 호출 방법을 기록합니다. API 키·개인 대화·연락처를 진단 로그에 넣지 않습니다.

## 별도 검증이 필요한 영역

- Google 로그인/세션 복원/재생목록은 SDK 비동기 경로가 있어 실제 계정에서 연결·해제
  중 응답 지연 검증과 중앙 정책 연동 정리가 별도로 필요합니다. 이번 수정으로 해당
  인증 흐름 전체가 안전하거나 경쟁 상태가 없다고 보증하지 않습니다.
- 이미 예약된 알람/일정 음성 파일, iOS 잠금·집중 모드·Siri 자체 음성은 실기기 범위입니다.
- 공유 데이터는 A 단계의 별도 동기화 DB이고 실제 예약 자동 반영은 아직 없습니다.
- 거대한 AssistantViewModel/설정 화면의 파일 분리는 기능별 회귀를 확보한 뒤 점진적으로
  진행해야 합니다. 파일을 옮기는 것만으로 이번 음성 문제나 일반화 성능이 해결되지는 않습니다.
