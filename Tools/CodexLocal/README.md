# JARVIS Codex 개인용 Mac 로컬 연결

## Codex 프로젝트 작업 · 1~6단계 통합 (2026.11.18.1)

프로젝트를 연결한 기본 채팅은 이제 **Codex 프로젝트 작업 · 승인 기반 호스트 도구** 모드를 사용합니다. `+` 메뉴의 같은 이름 토글을 끄면 기존 JSON 변경안 검토 방식으로 돌아갑니다. 코드 범위를 직접 첨부한 요청도 기존 검토 경로를 사용합니다. 일반 대화·이미지·PDF 메시지는 기존 경로를 유지합니다. 모드 전환이 미지원 런타임에 대한 자동 fallback은 아닙니다.

### 지원 검사와 실제 도구 경로

설치된 실행 파일의 버전과 해당 버전이 생성한 JSON 스키마를 검사합니다. `thread/start.dynamicTools`, `DynamicToolCallParams`, `DynamicToolCallResponse`가 확인돼야 시작하며, 프로토콜은 `agentVersion=2`입니다. 런타임이 바뀌면 지원 검사를 다시 합니다. 현재 실험적 API이므로 버전별 회귀 검증이 필요합니다. UI에 런타임 버전·호스트 도구 10종·실험적 API 여부를 표시합니다.

기존 최종 답변 JSON 반복과 별도로, **실제 App Server의 한 turn 안에서 `item/tool/call` → Swift 실행 결과 → Codex의 다음 도구 호출/최종 답변**이 이어집니다. 프로젝트 경로를 native cwd로 설정하고 명시적인 최근 코드 대화 최대 3쌍을 AssistantContextManager로 제한해 전달합니다. 이 모드의 작업 세션은 전용 프로필에 저장되지만 실행 승인은 저장·복원하지 않습니다. 재개 조건은 아래 5단계를 따릅니다.

| 모델 도구 | 결정론적 실행과 승인 |
| --- | --- |
| `jarvis_project_list` | 보호 규칙으로 걸러진 상대 파일 목록을 검토한 뒤 공유 |
| `jarvis_project_read` | 경로·줄 범위·원본·키 검사 후 미리보기 및 공유 승인 |
| `jarvis_project_edit` | 앞서 공유한 원본의 정확한 치환 또는 새 파일, 파일별 diff 검토·백업·원자적 저장·재확인 |
| `jarvis_project_verify` | 기존 Swift/Python/Xcode 검증 allowlist만 별도 승인, 소스 읽기 전용·scratch 쓰기·네트워크 차단, 출력 공유는 다시 검토 |

호스트 도구는 `CapabilityRegistry.codexAgentTools`에 등록하고 각 호출을 `AssistantIntent.codexLocal`과 SafetyPolicyEngine에 매핑합니다. 모델이 JARVIS 정책을 우회해 직접 파일·셸·네트워크를 실행하는 내장 도구/권한 요청은 여전히 거절합니다. 이 구현을 **제한 없는 Codex 내장 도구의 전면 활성화나 공식 앱 전체와의 동등성으로 표시하지 않습니다.** 보호된 안전·자격 증명·실행기·Codex 통합 소스는 수정할 수 없습니다. 새 하위 폴더 생성·임의 명령은 지원하지 않습니다. MCP·스킬은 아래의 별도 등록·승인 경로를 사용합니다.

### 5단계 · 저장된 프로젝트 작업 세션

`+` → **작업 세션·이력 관리…**에서 현재 폴더의 세션을 조회하고 보관/복원·영구 삭제·문맥 압축을 실행합니다. 최신 완료 답변에서 분기하면 확인된 native turn까지 `thread/fork`를 사용합니다. 과거 위치에서의 분기는 기존 제한된 문맥 재구성을 사용합니다.

- 대화 UUID·폴더 경로/기기 파일 식별자의 해시·확장 설정/프로토콜 버전 해시·마지막 완료 turn만 전용 `jarvis_agent_history.json`(0600)에 저장합니다. 원문·승인·키는 이 메타데이터에 넣지 않습니다. Codex 자체 대화/도구 기록은 전용 App Server 프로필에 남습니다.
- 앱이 마지막 답변을 저장한 turn과 helper 기록이 일치할 때만 재개합니다. 재시작·중단·로컬 저장 실패·프로젝트/확장 설정 변경으로 일치하지 않으면 승인이나 도구를 재생하지 않고 최근 최대 3쌍의 로컬 문맥으로 새 세션을 만듭니다. 이전 native 세션은 관리 목록에 남깁니다.
- 관리 작업은 개별 확인이 필요합니다. 압축도 모델 서비스를 사용하며 실제 contextCompaction/turn 완료까지 확인합니다. 결과가 불확실하면 대기 표식을 유지하고 자동 재시도하지 않습니다. 메타데이터 해제는 원본 삭제와 다르며, 영구 삭제도 JARVIS 로컬 채팅 메시지를 자동 삭제하지 않습니다.
- 메타데이터는 최대 600개이며 조용히 기존 기록을 버리지 않습니다. 손상 파일은 덮어쓰지 않습니다. 관리 목록은 50개, native 작업 요약은 10개씩 읽습니다. 세션 도구 출력 누적이 약 256KiB를 넘으면 명시적인 압축이 필요합니다.

### 6단계 · 모델이 선택하는 확장 도구

`+` → **작업 확장·스킬·검색 설정…**에서 MCP 정의를 가져오거나 기존 연결을 선택한 뒤, 허용할 도구 이름을 명시하고 내용을 검토해 저장합니다. 저장된 설정은 다음 작업부터 적용됩니다. 작업 시작 시 설정을 고정하므로 도중 변경으로 승인 대상이 바뀌지 않습니다.

| 추가 모델 도구 | 승인 경계 |
| --- | --- |
| `jarvis_extension_list` | 등록한 연결의 이름·ID·허용 도구 목록 공유 승인 |
| `jarvis_extension_inspect` | 지정 서버 연결 승인 → 허용 도구의 스키마만 결과 전송 검토 |
| `jarvis_extension_call` | 등록 서버·허용 도구 이름·인자별 실행 승인 → 출력 편집/전송 승인 |
| `jarvis_skill_list`, `jarvis_skill_read` | 사용자가 파일로 가져와 검토한 스킬 문서 목록·내용 공유 승인 |
| `jarvis_web_search` | 설정에서 켠 경우에만 검색어 전송 승인 → 결과와 출처 전송 검토 |

MCP는 최대 8개 연결, 연결당 20개 도구이며 서버 설정에 env·인증 헤더·키·훅을 넣을 수 없습니다. 필요한 OAuth는 기존 **도구 연결 설정**에서 별도로 처리합니다. 인증이 필요한 도구는 작업을 취소한 후 설정으로 이동할 수 있고 자동 재시도하지 않습니다. 지원하지 않는 입력 요청은 거절합니다. 기존 플러그인 관리로 설치한 MCP 정의도 검토 후 등록할 수 있으나 임의 플러그인 스크립트/훅을 자동 실행하지 않습니다.

스킬은 최대 4개, 문서당 16KiB로 제한합니다. 참고 자료로만 전달하며 스크립트를 실행하거나 안전 정책을 바꾸는 권한을 부여하지 않습니다. 검색은 기존 Tavily 서비스를 사용하며 별도 키를 Mac Keychain에 개별 승인 후 저장/삭제합니다. 키는 모델·공유폴더·설정 프로필에 전달하지 않습니다. 출처/도구 결과도 신뢰할 수 없는 자료로 취급합니다.

실제 계정의 OAuth 완료·유료 검색·모델의 도구 선택까지는 서비스별 실사용 검증이 필요합니다. 공식 앱 계정 전체 대화/설정 양방향 동기화, 제한 없는 내장 셸, 컴퓨터 제어는 구현 범위에 포함되지 않습니다.

### 승인·취소·결과의 경계

- 승인 카드는 프로젝트 도구의 인자와 실제 전송/변경 내용을 보여줍니다. `이번만 허용` 또는 `허용 안 함`으로 응답합니다.
- 읽기에만 같은 경로·줄 범위를 현재 작업에서 최대 8회 허용할 수 있습니다. 쓰기와 검증 명령의 포괄 승인은 제공하지 않습니다.
- job/thread/turn/call/approval 식별자를 묶고, 승인 2분·호스트 안전 여유 10초·전체 작업 10분·도구 최대 32회·추가 지시 최대 3회로 제한합니다. 소스 공유는 최대 8개 파일·96KiB입니다.
- 승인 전 원본을 다시 확인합니다. 프로젝트 교체·원본 변경·만료·중복·오래된 승인은 실행하지 않습니다.
- 작업 취소·화면 종료·대화/프로젝트/모델/추론/연결 변경·긴급 잠금은 승인을 폐기합니다. 시작 요청보다 취소 요청이 먼저 도착한 경우에도 나중에 작업을 시작하지 않습니다.
- 작업 진행·도구 승인 대기·출력 검토·완료/실패를 채팅에 표시합니다. `기기에서 확인한 실행 결과`는 모델 텍스트와 별도로 파일 저장·백업·검증 상태를 표시합니다. 검증 실패를 성공 결과로 돌려주지 않습니다.
- 변경 백업은 기존 프로젝트 백업 목록에서 개별 확인·복구할 수 있습니다. 백업 복구는 새 승인이 필요합니다. 추가 지시는 작업 중에만 보낼 수 있고, 전달 실패 시 입력을 보존하며 자동 재전송하지 않습니다.

검증에는 실제 로컬 HTTP 인증·실제 JSONL 가짜 프로세스·스키마/식별자 검증·Swift 실제 파일 변경/백업/취소/긴급 잠금/검증 실패 테스트를 사용합니다. 설치된 Codex에서는 임시 비로그인 프로필로 experimental initialize와 dynamic-tool thread/start까지 확인하며 모델 turn을 시작하지 않습니다. 실제 계정의 모델이 도구를 선택해 사용하는 실서비스 테스트와 구분합니다. 개인 자격 증명을 테스트가 읽거나 복사하지 않습니다.


## 대화형 개발 작업 (2026.11.11.3)

프로젝트가 연결된 기존 채팅에서 소스 확인 → 승인된 파일 변경 → 검증 제안 → 별도 실행 승인 → 출력 검토·전송 → 최종 설명을 이어갑니다. codeVersion 3은 선택적 toolResults와 검증 commands를 추가합니다. 구형 codeVersion 2는 최신 서비스 재시작을 안내합니다.

모델은 검증을 제안하며 Swift와 Python이 지원 명령을 각각 검증합니다. Swift build/test, Python unittest discovery, Xcode project/scheme build만 모델 제안 경로에서 실행합니다. 검증 프로세스의 cwd와 쓰기 권한은 별도 임시 디렉터리에 고정하고 소스는 읽기 전용으로 유지합니다. networkAccess는 false이고 최대 60초입니다. 수동 command·MCP 경로로 자동 전환하지 않습니다.

코드 읽기 작업 승인은 검토한 파일·줄 범위, 동일 작업, 최대 8회·10분에만 유효합니다. 변경과 검증은 매번 승인합니다. 작업은 최대 12회 모델 요청으로 제한합니다. 출력은 command/exec/outputDelta의 processId·스트림·base64를 검증하고 제한된 NDJSON delta로 전달합니다. 검증 실패·취소는 자동 재실행하지 않으며 다음 모델 요청에 넣을 출력은 사용자가 따로 검토합니다.

## 승인 기반 네이티브 도구 (2026.11.11.2)

채팅의 + 메뉴에서 **셸·MCP·플러그인 도구 실행**을 엽니다. App Server와 프로젝트 폴더가 연결되어 있어야 합니다. 실행할 프로그램·인자·프로젝트 또는 stdio MCP 서버·도구·인자를 검토한 뒤 이번 실행을 허용합니다. 플러그인 .mcp.json에서 command/args 서버 구성을 불러올 수 있습니다. 선택·목록 조회 승인은 다음 도구 호출 승인으로 재사용하지 않습니다.

명령은 `command/exec`의 프로젝트 쓰기 샌드박스, 네트워크 차단, 30초 제한을 사용합니다. MCP 서버는 Mac 사용자 권한으로 실행되므로 신뢰하는 프로그램만 실행하세요. MCP 도구 오류와 명령의 0이 아닌 종료 코드는 실패로 반환합니다. 양쪽 Swift·Python 검증과 프로젝트 식별자 확인을 통과해야 실행하며 중지·잠금은 전용 프로세스를 종료합니다. 출력은 검토 화면에만 표시합니다. 인증·환경 변수 구성, HTTP MCP, 플러그인 마켓·스킬·훅과 모델의 자동 도구 선택은 이번 범위에 포함되지 않습니다.

아래의 텍스트 대화 및 변경안 경로는 네이티브 도구 화면과 별도입니다.
연결 설정의 **CLI / App Server** 선택으로 두 방식을 병행합니다. 기본값은 기존 CLI이며 자동 fallback은 없습니다. App Server는 모델 응답을 생성하는 `turn/start`와 후속 세션을 사용하지만 파일·명령·승인 도구는 허용하지 않습니다.
App Server에서는 기본 채팅의 프로젝트 폴더 연결을 통해 코드 변경과 지원되는 검증을 요청할 수 있습니다. 모델의 읽기 요청은 상대 경로·줄 범위로 검증하고 로컬 미리보기 후 외부 전송 승인을 받습니다. 파일별 적용·백업 복구도 개별 승인을 받습니다. 임의 셸 실행·에이전트 협업·iPhone 원격 호출은 이 모델 경로에 없습니다. codeVersion 3이 필요합니다. 소스 읽기와 변경 적용은 Swift가 수행합니다.
로컬은 JARVIS↔보조 프로그램 연결만 의미합니다. Codex 답변 생성은 인터넷/OpenAI 서비스를
사용하며 ChatGPT/Codex 사용 한도가 적용됩니다. 무료·무제한·오프라인 추론 기능이 아닙니다.

## 앱에서 시작 (권장)

최신 Mac 앱을 빌드한 뒤 멀티 에이전트 → 연결 설정 → **보조 서비스 시작·자동 연결**을 승인합니다. Python 3·Codex 설치와 기존 로그인은 필요하지만 터미널 상시 실행·JSON 파일 선택은 필요하지 않습니다. 서비스 중지 버튼으로 종료합니다. 아래 수동 방식은 별도로 유지됩니다.

## 기존 수동 시작

1. Mac에서 Codex CLI에 **ChatGPT 계정**으로 로그인합니다. 기존 로그인을 사용하며 JARVIS는
   로그인 토큰/API 키를 복사하지 않습니다. API 키 인증으로 자동 전환하지 않습니다.
2. 프로젝트 루트에서 다음을 실행합니다. `python3`가 필요합니다.

```sh
python3 Tools/CodexLocal/jarvis_codex_local.py
```

CLI는 PATH, Homebrew 표준 위치, 설치된 ChatGPT 앱의 번들 CLI 순서로 찾습니다.
신뢰할 실행 파일을 직접 지정하려면 다음처럼 사용합니다. 번들 내부 경로는 앱 버전에 따라
바뀔 수 있으므로 자동 탐색 실패 시 공식 Codex CLI 설치 또는 `--codex` 지정을 사용하세요.

```sh
python3 Tools/CodexLocal/jarvis_codex_local.py --codex /신뢰하는/절대경로/codex
```

3. 터미널에 출력되는 `JARVISCodexLocal.json` 경로를 확인합니다. 기본 위치는
   `~/Library/Application Support/JARVISCodexLocal/JARVISCodexLocal.json`입니다.
4. **Mac JARVIS → 개발 공간 → 멀티 에이전트 → Codex 연결 설정 → 로컬 연결 파일 선택**에서 이 원본 파일을
   고르고 연결을 승인합니다. 파일 선택창에서 `⌘⇧G`로 위 폴더를 입력할 수 있습니다.
5. **로그인 상태 확인** 후 모델 목록을 자동으로 불러옵니다. 연결 설정 창을 닫고
   입력창 오른쪽 아래에서 모델·추론 수준을 선택하세요. 대화방이 없어도 선택할 수 있습니다.
   목록은 연결 설정 또는 입력창 모델 메뉴에서 수동으로 새로 고침할 수도 있습니다.
   최근 Codex 캐시의 모델 ID·이름만 읽으며 계정·지침 등 다른 메타데이터는 반환하지 않습니다.
   목록이 없으면 계정에서 지원하는 모델 ID를 직접 입력할 수 있습니다. 모델이 현재 사용 가능한지는 응답 시 확인합니다.
6. 아래 입력창에 메시지를 작성하고 전송 버튼 또는 **Enter**를 누르면 바로 전송합니다.
   **Shift+Enter**는 줄바꿈합니다. 반복 토큰 사용 알림·전송 확인 팝업은 표시하지 않습니다.
   입력창의 현재 메시지·선택 모델·대화에 대한 사용자의 전송 동작 자체를 개별 확정으로 처리합니다. 장기·백그라운드 승인은 저장하지 않으며 안전 잠금·중복 방지·연결 검사는 유지합니다.
   고정 질문 테스트는 연결 설정 창에 별도로 있습니다.
7. 중지는 대화창의 중지, 연결 해제는 연결 설정의 JARVIS 연결 해제를 사용합니다.
   보조 프로그램 자체는 터미널에서 `Control-C`로 종료합니다. 로그인 자체를 해제하지 않습니다.

JARVIS 창/화면 이탈·안전 잠금·연결 해제 시 요청을 취소합니다. 이미 처리된 요청은 한도를
소모했을 수 있으며 자동 재시도하지 않습니다. 앱 재실행/화면 재입장 후 연결 파일을 다시 고릅니다.
보조 프로그램 재실행 시 포트·연결 토큰이 변경되므로 기존 연결을 해제하고 다시 선택하세요.
앱만 업데이트해도 이미 실행 중인 Python 프로그램은 이전 코드를 계속 사용합니다. 보조 프로그램 변경 후에는 터미널에서 Control-C → 같은 명령으로 재실행 → 연결 파일 재선택이 필요합니다. 현재 응답은 `protocolVersion: 3`과 `backend`를 포함합니다. CLI는 이전 버전 2도 사용할 수 있고, App Server는 버전 3과 일치하는 backend를 요구합니다. 이 업데이트가 기존 CLI의 재로그인을 요구하는 것은 아닙니다.
로컬 HTTP 요청 형식 거절(400), 인증/지원 기능 불일치(401/403), 미지원 경로(404/405)는 각 원인과 재시작 방법을 표시합니다. 접속 자체 실패도 별도로 안내합니다. 이 오류들을 일괄적으로 사용량 소모 가능성이 있는 응답 확인 불가로 처리하지 않습니다. 시간 초과·중간 연결 손실 등 실제 처리 여부가 불명확한 경우에는 확인 불가 안내와 자동 재시도 금지를 유지합니다.

## 프로젝트·대화 기록

### App Server 첫 연결

1. 최신 보조 프로그램을 수동 재시작하고 Mac 앱의 연결 설정에서 **App Server**를 선택합니다.
2. 최신 앱에서는 App Server를 선택하고 **ChatGPT 로그인**을 누릅니다. 기존 CLI 설정·로그인과 분리하며 인증 파일을 복사하지 않습니다. 아래 명령은 수동 로그인 대안입니다.

```sh
CODEX_HOME="$HOME/Library/Application Support/JARVISCodexLocal/AppServer" codex login
```

`codex`가 PATH에 없다면 기존에 확인한 실행 파일의 절대 경로를 따옴표로 감싸 사용합니다. 이 Mac의 ChatGPT 앱 번들 경로는 다음과 같습니다.

```sh
CODEX_HOME="$HOME/Library/Application Support/JARVISCodexLocal/AppServer" "/Applications/ChatGPT.app/Contents/Resources/codex-cli/CodexCLI.app/Contents/MacOS/codex" login
```

3. 연결 파일을 선택하고 **로그인 상태 확인**을 누릅니다. App Server 초기화·계정 조회 후 모델 목록을 읽습니다.
4. 기존 입력창에서 Enter로 전송합니다. 대화 UUID를 helper 내부의 전용 ephemeral thread에 매핑하므로 후속 질문은 같은 native 세션에서 처리합니다. 서버 thread ID나 임의 RPC는 클라이언트가 지정할 수 없습니다.
5. 같은 native 세션에 쌓이는 문맥은 성공 문답 수·바이트로 제한합니다. 최근 문맥 불일치·최대 6회 누적·약 48KiB 예산 초과 예상 시, 이전 native thread를 해제하고 AssistantContextManager가 구성한 제한된 로컬 문맥으로 새 thread를 만듭니다. 최대 40개 native 대화를 관리합니다.
6. 중지 시 가능한 경우 `turn/interrupt`를 보내고 이번 전용 App Server 프로세스를 닫습니다. helper는 유지됩니다. 다시 상태를 확인한 뒤 **새로 명시한 요청**으로 이어갈 수 있습니다. helper/서버 재시작과 응답 유실 후에도 이전 turn을 자동 재실행하지 않습니다. 최근 로컬 문맥 복구이며 영구 native session 복구는 아닙니다.

App Server의 임시 작업 디렉터리는 사용자 프로젝트가 아닙니다. 전용 CODEX_HOME에는 config.toml/config.json/AGENTS/requirements를 넣지 마세요. 발견되면 덮어쓰지 않고 설정 격리 오류로 차단합니다. Codex는 이 폴더에서 자신의 인증·내부 메타데이터를 관리하므로 모든 내부 디스크 쓰기를 0으로 보장하는 기능은 아닙니다. JARVIS가 credential 원문을 읽거나 복사하지는 않습니다.

연결 방식 선택은 기존 요청을 다른 backend로 재실행하는 승인이 아닙니다. 명시적 선택·안전 정책·준비 상태 확인을 거쳐야 하며, 답변에는 사용한 backend를 표시합니다.

### 기록과 문맥

- 왼쪽에 프로젝트와 대화를 표시하고 오른쪽에 대화·하단 입력창을 배치합니다. 항목의 보조 클릭 메뉴에서 이름 변경·삭제를 할 수 있습니다.
- 프로젝트가 없는 상태에서 메시지 전송을 누르면 `일반 대화` 프로젝트와 대화방을 자동 생성합니다. 상단 `새 대화`는 기존 일반 대화 프로젝트를 재사용하고 새 대화방을 만듭니다. 프로젝트 내부의 `새 대화`는 해당 프로젝트에 만듭니다. 전송 취소 시에도 생성된 빈 대화방은 남습니다.
- 프로젝트 추가는 프로젝트 제목 옆 `+`에서 합니다. JARVIS 옆 폴더 추가 버튼은 제거했습니다.
- 모델·추론 메뉴는 입력창 오른쪽 아래에 있습니다. 선택한 모델·추론 수준을 대화방과 기본 선택값으로 보관합니다. 이전 버전 기록에서 누락된 추론 값은 낮음으로 해석하며 기존 기록을 교체하지 않습니다.
- 모델 버튼을 누르면 추천 모델 이름 8개와 선택 체크가 보이는 팝업을 즉시 엽니다. 연결·새로 고침 전에도 선택할 수 있고, 연결 해제나 빈 캐시 응답이 추천 목록을 지우지 않습니다. 연결 후 목록을 받으면 같은 모델의 지원 추론 정보를 병합하고 추가 모델도 표시합니다. 표시 자체는 모델의 현재 사용 권한을 뜻하지 않습니다.
- 입력창은 네이티브 일반 텍스트 위젯을 사용합니다. 안내 문구와 삽입 커서에 같은 글꼴·텍스트 시작 위치를 적용하며 Enter 전송·Shift+Enter 줄바꿈·붙여넣기·스크롤을 지원합니다. 숫자 키패드 Enter도 전송합니다. 한글 등 IME 조합 확정 Enter와 키를 길게 누를 때의 반복 이벤트는 전송하지 않습니다. 자동 링크·스마트 따옴표·대시 치환을 끕니다.
- 모델 목록에 지원 추론 수준이 있으면 그 값만 제시합니다. 모델 ID를 직접 입력하거나 이전 보조 프로그램의 목록을 사용하는 경우에는 기본 추론 선택지를 표시하며 실제 지원 여부는 요청 시 확인됩니다. 높은 수준은 응답 지연·사용량을 늘릴 수 있고 기존 시간 제한은 유지됩니다. 추론 설정은 셸·파일·하위 에이전트 권한을 부여하지 않습니다.
- 대화마다 모델을 저장하며 모델을 바꿔도 같은 대화의 제한된 문맥을 사용합니다. 다른 대화/프로젝트의 문맥은 보내지 않습니다.
- `AssistantContextManager`로 선택한 최근 최대 6개 성공 문답을 24,576바이트 안에 직렬화합니다. 더 오래된 기록은 화면에 남지만 전송 문맥에서 빠질 수 있습니다. 현재 입력은 6,000바이트, 답변은 8,192바이트까지입니다.
- CLI 모드의 매 요청은 격리된 새 CLI 실행에서 제한된 문맥을 재전달하는 방식입니다. App Server 모드는 위에서 설명한 제한된 ephemeral native 세션을 사용합니다. 어느 방식도 Codex 데스크톱의 기존 세션 ID·대화·권한을 가져오거나 임의 원격 Codex 세션을 재개하지 않습니다.
- 기록은 샌드박스 앱 지원 폴더의 `JARVISCodexWorkspace/workspace.json`에 저장합니다. 사용자 전용 폴더 700/파일 600 권한이며 별도 암호화 기능은 없습니다. 연결 토큰은 기록 파일에 저장하지 않습니다.
- 최대 프로젝트 20개, 프로젝트당 대화 30개, 대화당 메시지 200개, 전체 저장 파일 8MiB입니다. 한도 초과 시 자동 삭제하지 않습니다. 실패·중단도 화면에 표시하며 다음 모델 요청의 문맥에서 제외합니다.
- 손상 파일은 덮어쓰지 않습니다. 다른 창의 변경과 충돌하면 저장을 거절합니다. 다른 작업을 마친 뒤 대화 목록 새로 고침으로 다시 읽으세요. 앱 종료 시 대기 중이던 입력은 재실행하지 않고 중단 상태로 복구합니다.
- 프로젝트/대화 삭제에는 개별 확인이 필요하며 해당 로컬 기록만 삭제합니다. OpenAI 측 보관 기록을 삭제한다는 뜻은 아닙니다. iCloud 또는 iPhone으로 동기화하지 않습니다.

## 보호 경계

- JARVIS Mac 앱의 샌드박스를 유지합니다. 네트워크 클라이언트 권한을 추가했지만 앱의 이
  클라이언트는 하드코딩된 `127.0.0.1`만 사용하고 리다이렉트를 거절합니다.
- 보조 프로그램은 앱에서 승인한 내장 XPC 서비스 또는 사용자가 실행한 수동 터미널 프로그램으로 동작합니다.
  `127.0.0.1` 임의 포트에만 바인딩하고 고정된 인증 POST만 받습니다. 기존 status/probe/cancel/models/chat에
  App Server 전용 loginStart/loginPoll/loginCancel/logout과 읽기 전용 diagnostics를 추가했습니다. 임의 RPC를 받지 않습니다.
- 브라우저 Origin, 잘못된 Host, 임의 RPC·명령·파일 경로·다른 세션·재사용 요청 ID를 거절합니다.
  chat은 검증된 모델 ID·추론 수준과 현재 메시지·최대 6개 문답만 허용하며 시스템 지침·도구·권한 필드를 받지 않습니다. 추론 값은 고정 허용 목록으로 검사하고 CLI 설정 인자로 전달합니다. 추론 필드가 없는 이전 클라이언트는 낮음으로 처리합니다.
- 연결 파일은 사용자 전용 600 권한, 상위 폴더는 700 권한입니다. **이 파일은 로컬 연결 비밀정보를
  포함하므로 iCloud/공유 프로젝트/Git/메시지에 넣지 마세요.** OpenAI API 키나 로그인 토큰은 아닙니다.
- 고정 테스트는 시간당 10회, 대화는 시간당 60회, 세션당 총 요청 ID 1024개 한도가 있습니다. 최대 시간·출력량을 제한합니다. 인증 확인은 모델 호출에 포함하지 않습니다. 한도 도달 시 세션 재연결을 안내하며 이전 요청 ID를 조용히 재사용하지 않습니다.
  시작 시점 취소도 검사하며 자신이 만든 CLI 프로세스 그룹만 중단합니다.
- CLI는 임시 비프로젝트 폴더에서 실행합니다. 사용자 설정/규칙과 저장된 대화를 가져오지 않고,
  ChatGPT 인증을 강제하며 API 키 환경변수를 전달하지 않습니다. 셸·브라우저·컴퓨터 사용·MCP 앱·
  플러그인·훅·이미지·하위 에이전트 기능을 비활성화합니다. 읽기 전용 샌드박스를 사용합니다.
  daemon 자동 시작·무제한 통신 재시도도 비활성화합니다. CLI 내부의 유한한 통신 재시도까지
  과금 0회로 보장하는 것은 아니며 전체 실행 시간 제한과 불확실한 처리 안내를 적용합니다.
  필수 격리 옵션이 없는 CLI는 거절하며, 성공을 위해 안전 제한을 완화하지 않습니다.
- App Server는 별도 CODEX_HOME과 `--stdio --strict-config`, 동일한 도구 비활성화 플래그, read-only sandbox를 사용합니다. 임의 JSON-RPC 프록시가 없고 고정된 initialize/account-read/model-list/thread-start/thread-unsubscribe/turn-start/turn-interrupt만 adapter가 호출합니다. 서버가 도구·권한 승인·동적 도구 요청을 보내면 거절하고 전용 프로세스를 종료합니다. 계정 원문·인증 URL·토큰은 앱 응답에 포함하지 않습니다.

- Codex 자체 캐시/로그인 갱신 등 내부 동작은 CLI가 관리합니다. `--ephemeral`은 모든 내부

## 앱에 포함된 XPC 서비스

Mac 타깃은 `JARVISCodexService.xpc`에 두 Python 어댑터를 리소스로 포함합니다. 앱의 연결 설정에서 서비스 시작을 승인하면 launchd가 앱 전용 XPC 서비스를 실행합니다. 별도의 설치 파일·LaunchAgent·로그인 항목 등록은 필요하지 않습니다. 중지·연결 해제·앱 종료는 해당 서비스가 소유한 자식만 종료하며 기존 수동 helper는 건드리지 않습니다.

XPC API는 인자를 받지 않는 start/stop뿐입니다. 양쪽 peer는 번들 코드의 cdhash로 고정됩니다. `--managed` 모드는 descriptor를 디스크에 만들지 않고 private stdout → XPC → 앱 메모리로 전달합니다. stdin EOF는 양쪽 백엔드와 HTTP 서버를 종료합니다. 고정 loopback 주소·임시 포트·세션별 토큰은 기존 HTTP 검증을 그대로 사용합니다. 사용자가 시작 시 승인한 경우에만 같은 빌드·backend에서 10분 내 최대 2회 전송 계층을 복구합니다. 질문은 재전송하지 않습니다.

본체 sandbox는 켜져 있고, 서비스는 설치된 개인 Codex 및 로그인 저장소 접근을 위해 별도 비샌드박스 실행 파일입니다. 따라서 외부에서 명령·경로·설정·실행 파일을 전달받는 메서드를 추가해서는 안 됩니다. Python 3은 `/opt/homebrew/bin/python3`, `/usr/local/bin/python3`, `/usr/bin/python3` 순서로 확인합니다. Codex와 Python이 없는 Mac에는 설치가 필요하며, 현재 Mac 개인용 배포 범위입니다. 서비스와 본체를 함께 서명·빌드해야 합니다.

검증: `python3 Tools/CodexLocal/check_service.py --service <빌드된 JARVISCodexService.xpc 절대 경로>`는 임시 sandbox 앱으로 실제 XPC 시작·잘못된 HTTP 인증 거부·중지·재시작·취소를 검사합니다. 계정 조회나 모델 호출은 하지 않습니다.

### 인증·복구 프로토콜

텍스트 프로토콜 버전 3은 유지하며 인증 확장은 `authVersion: 1`을 별도로 요구합니다. `/loginStart`는 ChatGPT 관리형 OAuth만 시작합니다. 로그인 ID는 보조 프로그램 내부에만 있고 요청에서 임의 ID·계정·API 키·경로를 받지 않습니다. 공식 PKCE URL·로컬 콜백을 Python과 Swift 양쪽에서 검증합니다. 로그인 URL은 시작 응답에만 한 번 전달하고 저장·진단·로그에 남기지 않습니다. `/loginPoll`은 일치하는 완료 알림과 `account/read`를 모두 확인해야 completed를 반환합니다. 취소·3분 만료·연결 해제는 전용 인증 프로세스를 정리합니다. `/logout`은 전용 계정이 비어 있음을 다시 확인합니다.

자동 복구 승인은 메모리에만 보관합니다. 벽시계와 단조 시계로 10분을 제한하고 같은 backend·번들 코드 해시에서 최대 두 번 연결만 재생성합니다. 중단된 요청은 다시 보내지 않습니다. Codex 실행 파일의 inode·크기·수정 시각이 바뀌면 기존 RPC를 닫고 다음 명시적 상태 확인을 요구합니다. 설정에는 연결 방식과 복구 옵션만 남깁니다.

`check_auth_protocol.py --codex <절대 경로>`는 임시 CODEX_HOME으로 실제 인증 시작·대기·취소·빈 계정 로그아웃을 검사합니다. 브라우저·개인 로그인·모델 호출은 사용하지 않습니다. 사용자가 브라우저에서 실제 계정 인증을 완료하는 과정은 별도 수동 검증이 필요합니다.


## 세션·확장 도구·결과 파일 (2026.11.11.4)

- **세션 계속/분기:** 일반 텍스트 대화는 전용 App Server의 실제 thread ID와 마지막 확인된 turn의 해시를 비공개 `jarvis_sessions.json`(0600)에 기록합니다. 재시작 후 같은 마지막 대화가 확인되면 `thread/resume`, 최신 답변에서 분기하면 `thread/fork`를 사용합니다. 별칭은 최대 40개이며 인증 정보·원문을 별칭 파일에 저장하지 않습니다. 공식 ChatGPT 앱과의 계정 대화/설정 양방향 동기화와는 별도입니다. 실패/중단으로 수신이 불확실하거나 이력이 다르면 자동 재실행하지 않고 제한된 로컬 문맥으로 새 세션을 만듭니다. 오래된 분기, 6회 후속 요청 또는 문맥 용량 초과도 새 세션입니다. Codex 자체의 실제 세션 기록은 전용 프로필에 남을 수 있습니다. 별칭 제거가 서버 측 기록 삭제를 뜻하지 않습니다.
- **작업 재검토:** 중단된 코드 작업은 이 Mac에 요청·모델·추론 설정·폴더 식별자·시각만 최대 7일간 보관합니다. 원본 코드, 실행 출력, 쓰기·명령 승인은 복구 기록에 저장하지 않습니다. 같은 폴더를 다시 연결한 뒤 ‘다시 검토·시작’을 눌러야 새 작업이 시작됩니다. 원본·필요한 허가를 다시 확인하고 이전 명령을 재생하지 않습니다. 명시적 중지·기록 지우기·정상 완료는 복구 기록을 삭제합니다.
- **HTTP MCP/OAuth:** stdio 및 HTTPS(개발용 HTTP는 loopback만), 수동 로그인 시작/브라우저 열기/완료 확인을 지원합니다. 토큰을 URL·연결 설정에 넣지 않습니다. OAuth 토큰은 Codex가 관리하고 JARVIS가 읽거나 복사하지 않습니다. 연결 정의는 이 Mac에 최대 20개 저장할 수 있습니다. 설정 삭제는 OAuth 토큰 폐기가 아니므로 서비스 측 권한 관리가 별도로 필요합니다. 로그인 대기는 3분, 각 도구 호출은 제한 시간이 있고 취소 시 연결 프로세스를 닫습니다.
- **플러그인:** 설치된 Codex CLI의 `plugin list/add/remove/marketplace add`로 목록·마켓·설치·제거를 관리합니다. 개발 중인 App Server plugin RPC는 사용하지 않습니다. 플러그인 라이브러리는 별도 `PluginLibrary` 프로필이며 필요한 경우 별도로 로그인합니다. `.mcp.json`은 서버별 내용 검토 후 실행하고, Skill 문서는 선택한 텍스트 파일로 참고할 수 있습니다. 설치가 모델의 자동 도구 실행·훅 실행 승인으로 확대되지 않습니다. 모든 공식 플러그인의 전용 UI/자동 실행과의 동등성을 보장하지 않습니다.
- **Git/오류:** 도구 창에서 프로젝트 Git 상태와 파일별 작업 트리/스테이징 diff를 조회합니다. Git hook·외부 diff·textconv를 실행하지 않으며 커밋·스테이징은 이 UI에서 하지 않습니다. 기존 파일별 승인 적용·백업 복구를 유지합니다. 검증 출력의 `파일:줄:열:`은 프로젝트의 실제 파일 목록과 일치할 때만 소스 미리보기로 연결합니다.
